# V2 release readiness review

Review of `master` at `10d6000d` (2026-10-09) against `v2.0.0-alpha.3`, covering the release process, the standalone `pkg/*` modules, and scaffolded application code.

## Verdict

- **alpha.4:** ship after the [release blockers](#release-blockers) and the two security items marked _alpha.4_ are fixed.
- **beta:** additionally requires every item marked _beta_.

Tests, vet, lint, and full goldens pass on HEAD (nightly `ci-nightly`). The blockers are in the release gate, the upgrade path, generated auth code, and `pkg/hypermedia`.

Each item has an ID for tracking in issues and PRs. Severity: **H** high, **M** medium, **L** low.

### R1 — Release Readiness is red on `master`

`docs/releasing.md` forbids tagging until the check is green. It fails at `just vulncheck` on GO-2026-6629 (`golang.org/x/text` v0.39.0, fixed in v0.41.0), reachable from `cli/database.go:700` via `pgx.Connect`. Race tests and full goldens are skipped on that run because vulncheck fails first.

- [x] Bump `golang.org/x/text` to v0.41.0 or later in the root `go.mod`. Minimum version selection also raised `golang.org/x/tools` to v0.48.0 and `golang.org/x/mod` to v0.38.0.

### R2 — Go 1.27.1 has reachable standard library vulnerabilities

A local `govulncheck` reports nine reachable vulnerabilities in `net/http`, `net/http/internal/http2`, `net/textproto`, and `crypto/tls` (GO-2026-6603, 6605, 6607, 6608, 6610, 6611, 6612, 6613, 6617), all fixed in Go 1.27.2. CI has not reported them yet only because its last scan predates their publication. The next readiness run will fail on them after R1 is fixed.

- [x] Go version pins in all seven workflows: `release-readiness.yml`, `release.yml`, `release-artifact-preflight.yml`, `nightly.yml`, `e2e-nightly.yml`, `test.yml`, `golden-files.yml`
- [x] Root `go.mod` and `go.work`
- [x] `goVersion` in `layout/layout.go:728`, plus the four `testdata/golden/new/*/go.mod.golden` files it produces, so new applications do not start on a vulnerable toolchain
- [x] Go version badge in `README.md`
- [ ] `pkg/*` `go.mod` minimums. Deliberately unchanged because each change needs a package release. Handle it with the `pkg/*` vulncheck item under [Release hygiene](#release-hygiene).

### R3 — Upgrading an alpha.3 application to alpha.4 breaks compilation

`andurel upgrade` bumps the narsilc tool in `andurel.lock` to v0.5.0 (`layout/upgrade/orchestrator.go`, tool sync). `planVerifiedPackagePins` (`layout/upgrade/plan.go:195-222`) pins only `github.com/mbvlabs/andurel/pkg/*`, so `github.com/mbvlabs/narsilc` stays at v0.4.5 in `go.mod`. Code generated by narsilc v0.5.0 calls `narsilc.Read`, `narsilc.FromRow`, and `narsilc.Transformer`, none of which exist in v0.4.5.

- [ ] Pin `github.com/mbvlabs/narsilc` to `versions.NarsilcModule` during upgrade, using the same no-downgrade rule as `pkg/*`.
- [ ] Add a test that covers the pin.

### R4 — The V2 CLI will "upgrade" a V1 project

`Upgrader.validatePreconditions` has no major-version guard. A `1-5-stable` project (lock version `v1.5.x`) gets a plan built from V2 templates and `pkg/*` pins. This contradicts the "no V1 to V2 path" policy in `plans/version-two.md`.

- [ ] Refuse to upgrade when the lock version's major is below the CLI's major, with an error that points to `1-5-stable`.

### R5 — Upgrade notes misfire for pre-release applications

`crossesVersion` uses `semver.Compare`, and `v2.0.0-alpha.N < v2.0.0`. Every alpha or beta application that upgrades to `v2.0.0` therefore receives the `telemetry-package-v2.0.0` and `inertia-vite-fullurl-v2.0.0` notes, although it already has those changes. The V1-era notes (`session-cookie-recovery-v1.5.4`, the renderer injection at `v1.5.6`) still ship and reference gorilla securecookie and echo-contrib session APIs that V2 no longer uses.

- [ ] Gate V2 notes on the first pre-release that contained the change, or drop notes that only apply to V1 to V2 migration.
- [ ] Remove the V1-only notes from the V2 CLI.

### R6 — No upgrade test covers V2

Upgrade fixtures are all V1 (`v1.0.3 → v1.1.0`, `v1.5.x`). R3 would have been caught by a V2 fixture.

- [ ] Add an alpha.N to HEAD upgrade test that also compiles the result.

### R7 — Release notes are empty

The `v2.0.0-alpha.3` GitHub release body is just `## Changelog`, because `.goreleaser.yaml` excludes `^chore:` and nearly every recent commit uses that prefix.

- [ ] Write release notes by hand for pre-releases, or adjust the changelog filters and commit prefixes.

### S1 — Email verification codes allow account takeover

- `Tokens.CreateCode` (`layout/templates/models_token.tmpl`) generates six characters from A–Z0–9, about 2.2 × 10⁹ values, valid for 24 hours.
- `Tokens.FindByScopeAndHash` looks a code up by scope and hash only. It is not bound to the email or session that requested it, so any pending user's code matches.
- `ConfirmationCreate` has no rate limit (`controllers_confirmations.tmpl`, `controllers_confirmations_inertia.tmpl`).
- `Confirmations.Create` signs the requester in as the user who owns the matched code.

An attacker who sprays codes signs in as an arbitrary freshly registered user. The expected work drops with every pending registration.

- [ ] Bind verification to the user: carry the email or a signed pending-user reference in the session, and query by it.
- [ ] Add per-account and per-IP attempt limits, and invalidate the code after N failures.
- [ ] Do not sign the user in on confirmation, or only sign in the session that registered.

### S2 — Script injection in `pkg/hypermedia` script helpers

The helpers build JavaScript with Go's `%q`, which escapes neither `<` nor `/`. `Prefetch` interpolates URLs with `"%s"` and no escaping. Datastar parses the resulting `<script>` as an HTML fragment, so a value that contains `</script><img src=x onerror=…>` executes. Affected locations:

- `pkg/hypermedia/script.go:83` (`Redirect`), `:95` (`ReplaceURL`), `:115` (`Prefetch`)
- `pkg/hypermedia/broadcaster.go:204` (`ConsoleLog`), `:215` (`ConsoleError`), `:227` (`Redirect`), `:262` (`DispatchCustomEvent` selector), `:303` (`ReplaceURL`), `:322` (`Prefetch`)
- `pkg/hypermedia/sse.go:182` (`DispatchCustomEvent` selector)
- `pkg/hypermedia/options.go:44`: script attribute values are not escaped

`%q` also emits `\U0001F600`-style escapes, which JavaScript does not understand, so non-BMP characters are corrupted.

- [ ] Encode JavaScript string literals with `json.Marshal`, which escapes `<`, `>`, and `&` by default, instead of `%q` or `"%s"`.
- [ ] HTML-escape attribute values.
- [ ] Add tests that use `</script>`, `<!--`, quotes, and emoji payloads.
- [ ] Update the `pkg/hypermedia` CHANGELOG and release a patch.

### S3 — The login and registration rate limiter is global behind a proxy

`IPRateLimiter` (`layout/templates/router_middleware_auth.tmpl:33`) keys on `c.RealIP()`. In Echo v5.3.0, that returns `RemoteAddr` when `IPExtractor` is unset, and the generated router never sets one. Behind any reverse proxy, every user shares one bucket of 5 requests per 10 minutes.

Further limitations:

- The limiter is in-memory and per process.
- It is capped at 1000 entries (LRU), so a flood of distinct IPs resets counters.
- It answers `429` with the redirect URL as the response body.

- [ ] Add trusted-proxy configuration (for example `HTTP_TRUSTED_PROXIES`) and set `echo.IPExtractor` with `echo.ExtractIPFromXFFHeader(echo.TrustIPRange(…))`.
- [ ] Return a meaningful 429 response.
- [ ] Apply the limiter to `ConfirmationCreate`, `PasswordCreate`, and `PasswordUpdate` (S1).

### S4 — Sessions cannot be revoked

The generated jar uses the stateless `kiks.CookieStore`, and `cookies.App` carries `IsAdmin`. Logout, password reset, and admin demotion leave other copies of the cookie valid for up to `SESSION_MAX_AGE` (7 days by default).

- [ ] Add a per-user session version or generation to the user record, store it in the cookie, and check it in `AuthOnly`. Alternatively, productize the database-backed store.
- [ ] Resolve admin status from the database instead of the cookie.

### S5 — Login timing reveals which emails have accounts

`Identity.AuthenticateUser` (`services_authentication.tmpl`) returns immediately for an unknown email and runs Argon2 only for known ones.

- [ ] Run a dummy Argon2 comparison on the not-found path.

### S6 — Generated controllers leak internal errors

Generated CRUD controllers flash `fmt.Sprintf("Failed to create widget: %v", err)` to end users, which exposes database and constraint text. See `testdata/golden/generate/controller/full_crud/controllers/widgets.go.golden`.

- [ ] Log the error and flash a generic message, keeping validation errors user-facing.

### C1 — No production email transport

`NewEmailSenders` (`layout/templates/runtime_runtime.tmpl:89`) supports only the `mailpit` driver, which uses `smtp.SendMail` with no authentication. Registration requires email verification, so a deployed application cannot onboard users without writing its own sender.

- [ ] Add at least one production driver, such as generic SMTP with authentication and TLS, or an API provider.
- [ ] Select the driver with `EMAIL_PROVIDER` and fail startup in production when it is `mailpit`.

### C2 — The HTTP server can fail to bind while the process keeps running

`startServer` (`layout/templates/runtime_server.tmpl`) runs `ListenAndServe` in a goroutine and returns `nil` from `OnStart`. A failed bind (port in use, permissions) is only logged. Fx keeps running and the process appears healthy while serving nothing.

- [ ] Call `net.Listen` synchronously in `OnStart` and return its error, then `Serve` in the background.
- [ ] Have `pkg/server` expose a listener-based start.

### C3 — Registration can strand a user

`Identity.RegisterUser` (`services_registration.tmpl`) commits the user and token, then enqueues the email with `Insert` outside the transaction. If the enqueue fails, the user exists without a code. There is no resend flow, and re-registering hits the unique-email constraint, which surfaces as a silent redirect.

- [ ] Enqueue with `InsertTx` inside the registration transaction.
- [ ] Add a resend-verification flow.
- [ ] Map a duplicate email to a validation error, phrased to avoid account enumeration.

### C4 — Failed login, verification, and registration give no feedback

On the Datastar path, `Sessions.Create`, `Confirmations.Create`, and `Registrations.Create` redirect with a 303 and no flash on non-validation errors. The form re-renders without a message.

- [ ] Flash a message, or re-render with a generic error ("Invalid email or password", "Invalid or expired code").
- [ ] Check the Inertia variants for the same behavior.

### C5 — `pkg/storage` links test infrastructure into production binaries

`pkg/storage/psql.go` imports `testing` and `testcontainers-go`. Every generated application's production binary therefore links the Docker SDK and runs its package `init` functions. This is also the source of the `moby/go-archive` vulnerability.

- [ ] Move `TestCluster` and `NewTestDB` to a separate package or module, for example `pkg/storage/storagetest`, and amend `plans/version-two.md`, which currently forbids that split.
- [ ] Alternatively, guard them with a build tag.

### C6 — SSE streams end at the HTTP write timeout

The `pkg/server` and generated defaults set `WriteTimeout` to 30 seconds. `hypermedia.NewBroadcaster` never clears the write deadline, so long-lived Datastar streams are cut after 30 seconds.

- [ ] Call `rc.SetWriteDeadline(time.Time{})` in `NewBroadcaster`, or document the setting.

### C7 — Generated CRUD controllers return the wrong status codes

- A `Bind` failure in `Create` and `Update` renders `views.NotFound()` instead of `views.BadRequest()`.
- Any `Find` error in `Show` and `Edit`, including database outages, renders 404. Only `models.ErrNotFound` should.
- In `Paginate`, a large `page` overflows `int32(offset)` into a negative `OFFSET`.

- [ ] Fix the status mapping in the controller generator and the paginate template.

## Reviewed and found sound

- `pkg/kiks`: cookie definitions, corrupt-cookie recovery, flash persistence rules, and the deferred-persist writer.
- Generated CSRF: Sec-Fetch-Site first, with a token fallback and a bearer-only API bypass.
- `pkg/inertia`: partial reload scoping, the protected `errors` prop, the 409 version mismatch, and `PageScript` escaping.
- `pkg/storage`: `RunInTransaction`, the `Transaction` boundary, and the River adapters.
- `pkg/inertia` SSR runtime lifecycle. `cmd/ssr` exits on runtime failure, so a supervisor restarts it.
- The verified package version set in `layout/versions/versions.go` matches the latest `pkg/*` tags.

## Not covered

The review read the code; it did not run a generated application. `pkg/telemetry`, `pkg/validation`, `pkg/inertia/ssr_http.go`, `pkg/routing/routes.go`, and the generator internals were only skimmed. The frontend templates and the new `console` and `dblab` commands were not reviewed.
