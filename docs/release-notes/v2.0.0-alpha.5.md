# v2.0.0-alpha.5

This pre-release moves the framework runtime out of generated applications and
into standalone Go modules. Generated applications now depend on `pkg/*` like
any other library, so framework fixes ship without rewriting application code.

## Highlights

- **Framework code moved into `pkg/` modules.** The generated runtime, config,
  handlers, middleware, and domain services now import
  `github.com/mbvlabs/andurel/pkg/*` instead of carrying copied framework code.
  Applications keep ownership of `internal/runtime`, domains, services,
  handlers, routes, and middleware.
- **New `pkg/auth`, `pkg/env`, and `pkg/lifecycle` modules.** `pkg/auth` owns
  argon2id password hashing, peppers, verification codes, and token hashing;
  `pkg/env` loads `.env` files and typed environment values; `pkg/lifecycle`
  owns signal-aware startup, shutdown stacks, and blocking servers.
- **Domain `Validate()`.** Generated domains expose a `Validate()` method built
  on `pkg/validation`, including the new `Email` rule. The handler and service
  layers call it directly; `validation.Validate` is deprecated.
- **Transactions and row locks.** `storage.AtomicOps` with a
  `storage.Transactor` is the only commit/rollback boundary. Receivers and the
  queue bind to it with `InTx`, and generated user reads use `FOR UPDATE` for
  read-modify-write flows.
- **Agent-first scaffolding.** The scaffold ships one test per layer, static
  file serving, rate limiting, an Inertia error handler, and generated
  `patterns show domain` output that renders entity files from narsilc rows.

## Upgrade notes

`andurel upgrade` from `v2.0.0-alpha.4` pins the package versions above and
prints the manual actions that application-owned code needs. Follow every
action before building:

- Update `internal/runtime` for `anduin.NewServer`, `Server.Start`,
  `cache.Store.Close`, and `inertia.RendererConfig`.
- Move test-cluster helpers from `pkg/storage` to
  `pkg/storage/storagetest`.
- Run `go mod tidy`, `gofmt`, `go fix ./...`, and `go vet ./...`.

Projects before `v2.0.0-alpha.4` use the pre-rebuild Echo/Fx layout and cannot
be upgraded automatically. There is still no V1 to V2 upgrade path; V1 projects
stay on `1-5-stable`.
