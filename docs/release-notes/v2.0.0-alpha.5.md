# v2.0.0-alpha.5

This pre-release moves the framework runtime out of generated applications and
into standalone Go modules. Generated applications now depend on `pkg/*` like
any other library, so framework fixes ship without rewriting application code.

## Highlights

- **Framework code moved into `pkg/` modules.** The generated runtime, config,
  handlers, middleware, and domain services now import
  `github.com/mbvlabs/andurel/pkg/*` instead of carrying copied framework code.
  Applications keep ownership of `internal/runtime`, domains, services,
  handlers, routes, and middleware.
- **New `pkg/auth`, `pkg/env`, and `pkg/lifecycle` modules.** `pkg/auth` owns
  argon2id password hashing, peppers, verification codes, and token hashing;
  `pkg/env` loads `.env` files and typed environment values; `pkg/lifecycle`
  owns signal-aware startup, shutdown stacks, and blocking servers.
- **Domain `Validate()`.** Generated domains expose a `Validate()` method built
  on `pkg/validation`, including the new `Email` rule. The handler and service
  layers call it directly.
- **Transactions and row locks.** `storage.AtomicOps` with a
  `storage.Transactor` is the only commit/rollback boundary. Receivers and the
  queue bind to it with `InTx`, and generated user reads use `FOR UPDATE` for
  read-modify-write flows.
- **Agent-first scaffolding.** The scaffold ships one test per layer, static
  file serving, rate limiting, an Inertia error handler, and generated
  `patterns show domain` output that renders entity files from narsilc rows.

## Email

- **SMTP transport.** `pkg/email` gains `SMTPConfig` and `NewSMTP`, a production
  sender with STARTTLS, implicit TLS, plaintext local relays, PLAIN
  authentication, context cancellation, and typed temporary/permanent errors.
  TLS certificate verification failures are permanent, so a misconfiguration is
  not retried forever.
- **Mailpit fixes.** Messages no longer write a `Bcc` header; Bcc recipients
  travel only in the SMTP envelope. Headers now include `Date` and
  `Message-ID`, use a random multipart boundary, and RFC 2047 encode non-ASCII
  subjects and display names. Invalid addresses and embedded newlines are
  rejected, preventing header injection, and bodies are quoted-printable
  encoded. Attachments are sent as base64 `multipart/mixed` parts. Mailpit
  honours the send context.
- **Mailpit is refused in production.** With `ENVIRONMENT=production`, the
  scaffold refuses `EMAIL_PROVIDER=mailpit` and requires `smtp`.

## Authentication and security

- **Revocable sessions.** A new `users.session_version` column is carried in the
  session cookie and checked against the database on every authenticated
  request. `middleware.AuthOnly(users)` reloads the user, rejects a deleted user
  or a stale version, and exposes a database-backed viewer. A password reset
  bumps the version, so every other session stops working immediately.
- **PHC password hashes.** `pkg/auth` writes argon2id PHC strings. Existing
  `base64hash:base64salt` hashes keep verifying and are rewritten in the current
  format on the next successful login; a previous pepper also triggers a
  rehash. Applications need no changes.
- **Constant-time login.** The unknown-email path runs `auth.DummyVerify` so it
  spends the same argon2 work as a real password check.
- **Generic auth responses.** Duplicate registration answers like a successful
  sign-up instead of confirming that the address exists, invalid or expired
  reset codes return one generic message, and the rate-limit page asks the user
  to retry later.

## Routing, cookies and Inertia

- **`routing.Hosts` value.** The package-level host registry is gone.
  `routing.NewHosts` validates and returns an immutable `*routing.Hosts`; the
  router takes it with `anduin.WithHosts`, and every `FullURL` call takes it as
  the first argument. This replaces `ConfigureHosts`, `LookupHost`, `Hosts`, and
  `HostBaseURL` (breaking).
- **Per-cookie kiks lifetime.** `MaxAge` now applies to each cookie definition
  instead of the whole jar, so a short session no longer expires longer-lived
  cookies. `NewJar` and `NewCookieStore` reject an encryption key that is not
  16, 24, or 32 bytes. Alpha.4's `.env.example` already generated a 32-byte key,
  so existing projects keep working.
- **Inertia escaping.** Page JSON is HTML-escaped in both the JSON response and
  `PageScript`, so a prop containing `</script>` or `<!--` cannot break out of
  the document.
- **`validation.Validate` removed.** The deprecated `Validate` function and
  `Validatable` interface are gone (breaking); call the value's `Validate`
  method and join errors with `validation.Join`.
- **Pagination and test clusters.** `storage.Page` clamps huge page numbers, and
  `storagetest` database names no longer collide under parallel tests.

## Dependencies and tooling

- **Security bumps.** `golang.org/x/net` v0.60.0 (GO-2026-6617, GO-2026-6612,
  GO-2026-6611, GO-2026-6610, GO-2026-6603), `golang.org/x/crypto`, `grpc`
  v1.83.2 (GO-2026-6443), and `moby/go-archive` are updated across the `pkg/*`
  modules.
- **CI hardening.** `just vulncheck` now scans the root module and every
  standalone `pkg/*` module. `ci-pr` runs `check-fmt`, `check-fix`, lint and
  vulncheck, so a PR fails before `master` does.
- **Upgrade end-to-end test.** `TestUpgradeAlpha4ToHEAD`
  (`just test-upgrade-e2e`) scaffolds a real `v2.0.0-alpha.4` app, upgrades it
  with this checkout, applies the reported manual actions, and requires the
  result to build and vet. `ANDUREL_UPGRADE_E2E_LOCAL_PKG=1`
  (`just test-upgrade-e2e-local`) also replaces every `pkg/*` with the local
  checkout for branches whose package changes are not published yet.
- **Nightly E2E.** `scripts/e2e.sh` drives the agent loop on a fresh app: `new`,
  tool sync, migrate, verify, the domain manifest for a new entity, sync
  queries, inspect domains, then build, boot and poll `/health`.

## Upgrade notes

`andurel upgrade` from `v2.0.0-alpha.4` pins the package versions above and
prints the manual actions that application-owned code needs. Follow every
action before building:

- **Package APIs.** Update `internal/runtime` for `anduin.NewServer`,
  `Server.Start`, `cache.Store.Close`, and the `inertia.RendererConfig` and
  `inertia.SSRRuntimeConfig` constructors. Add River's main-line migration 7.
- **Storage test helpers.** Move test-cluster helpers from `pkg/storage` to
  `pkg/storage/storagetest`.
- **Routing hosts.** Remove `routing.ConfigureHosts` from `config.NewApp`, build
  `hosts, err := routing.NewHosts(cfg.App.Hosts)`, pass it with
  `anduin.WithHosts(hosts)`, and thread it through `services.NewIdentity` and
  every `FullURL(hosts, ...)`, including the Inertia `BuildPathURL`.
- **Session revocation (recommended).** Add the `session_version` migration and
  queries, `BumpSessionVersion`, the `SessionVersion` cookie field instead of
  `IsAdmin`, and `middleware.AuthOnly(users)`. This is a security fix; an
  alpha.4 app still compiles without it.
- **SMTP (optional).** `newEmailSenders` takes `config.App` and supports SMTP.
  Production apps still on Mailpit must switch.
- **Validation.** Replace `validation.Validate(&entity)` with
  `entity.Validate()` in `domains/user.go` and `domains/token.go`.
- **PHC hashes** need no action: existing hashes verify and are rehashed on the
  next successful login.
- Run `go mod tidy`, `gofmt`, `go fix ./...`, and `go vet ./...`.

Projects before `v2.0.0-alpha.4` use the pre-rebuild Echo/Fx layout and cannot
be upgraded automatically. There is still no V1 to V2 upgrade path; V1 projects
stay on `1-5-stable`.
