# v2.0.0-beta.1

The first V2 beta. The architecture is now fixed: `net/http` through
`pkg/anduin`, explicit construction in `internal/runtime`, the
`domains`/`handlers` layout, Inertia for the UI, and the agent-facing CLI
contract. From here on, a change to application code or a `pkg/*` API ships
only to fix a bug, a security problem, or a mistake found while building on the
beta, and always with an upgrade manual action.

## Highlights

- **Stability policy.** [`docs/stability.md`](https://github.com/mbvlabs/andurel/blob/master/docs/stability.md) states what
  beta and stable releases guarantee for generated code, the `pkg/*` modules,
  and the CLI's commands, flags, structured output, and manual action IDs.
- **Upgrades from every supported pre-release are tested.** Release readiness
  scaffolds with the released `v2.0.0-alpha.4` and `v2.0.0-alpha.5` CLIs,
  upgrades each app to this release, applies every manual action, and requires
  the result to build and vet.
- **Go 1.27.3 everywhere.** Every `pkg/*` module now requires Go 1.27.3, which
  matches generated applications, CI, and `govulncheck`.

## CLI

- `andurel upgrade` help and the CLI catalog describe what an upgrade does in
  V2: it re-pins `pkg/*` modules, synchronizes tools, and lists manual actions.
  It never rewrites application source.

## Documentation

- `docs/generated-files-and-upgrades.md` describes the V2 ownership model,
  supported upgrade paths, and every alpha.5 manual action.
- Removed the V1 release-candidate upgrade prompt from the V2 branch. V1
  projects keep using `1-5-stable`.

## Known issues

- `GO-2026-5932` (`crypto/openpgp` in `golang.org/x/crypto`) has no fixed
  version. `pkg/auth` and `pkg/storage` require the module but never call the
  affected package, so `govulncheck` does not report it as reachable.

## Upgrade notes

Upgrading from `v2.0.0-alpha.5` reports no manual actions. Run:

```text
andurel upgrade
go mod tidy
go vet ./...
```

Upgrading from `v2.0.0-alpha.4` reports the alpha.5 manual actions; see the
[`v2.0.0-alpha.5` release notes](https://github.com/mbvlabs/andurel/releases/tag/v2.0.0-alpha.5) and
`docs/generated-files-and-upgrades.md`.

Projects before `v2.0.0-alpha.4` cannot be upgraded automatically. There is no
V1 to V2 upgrade path; V1 projects stay on `1-5-stable`.
