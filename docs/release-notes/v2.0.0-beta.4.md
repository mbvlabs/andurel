# v2.0.0-beta.4

Fixes from the beta.3 retest and the round-3 site port: a public welcome page,
production SSR defaults and readiness, isolated builds, truthful CLI discovery,
scoped verification, a smaller scaffold layout, and package APIs for routing,
storage testing, validation, and capability tokens.

## Scaffold and runtime

- Generated applications have no top-level `internal/`. Composition lives in
  `app/` (`app.New`, `app.NewQueue`), the configuration check is the `main`
  package in `cmd/configcheck`, and `domains/internal/queries` stays internal
  because only domains may import generated queries.
- `payloads/` is the single source of TypeScript payload types, like `routes/`
  is for `routes.ts`. Every exported struct in `payloads/` is emitted to
  `resources/js/types/payloads.ts`; handlers import it for page props and
  request bodies. Handler discovery of `FromStruct` roots, decode targets, and
  `Payload`-suffixed structs is gone. `payloads/` may import only the standard
  library and mappable types; the `payloads-import` rule rejects app, storage,
  and transport packages.
- The scaffold ships no `AGENTS.md`. Layer placement, HTTP, CLI, and testing
  guidance ships as CLI-owned skills, kept current by `andurel skill install`
  and upgrade.
- The welcome page is public; authentication middleware still protects private
  routes.
- Production Inertia pages use the renderer-wide SSR default. `.CSR()` opts a
  page out and `.SSR()` preserves explicit opt-in. Development retains per-page
  SSR. Inertia JSON visits are unaffected.
- `/api/health` is liveness; `/api/ready` checks database and required SSR
  availability. Readiness returns 503 with a stable reason while unavailable
  and recovers when its dependencies recover.
- Error mappings remain client-rendered to avoid recursive SSR failures. The
  scaffold configures its themed error component; the library also provides a
  safe HTML response when no application fallback component is configured.
- Server-side route origins are scoped to each render. Full-URL helpers fail
  clearly before host configuration; `.path()` remains configuration-free.
- The generated SSR executable propagates child failures to its exit status.
- The generated worker queue attaches telemetry to the River `Start` context,
  which River propagates to every job, instead of only passing the telemetry
  logger to River. Job logs and spans use the worker's providers.
- Routed HTTP spans and logs record the route template, never the raw
  `url.path` or query. An unmatched request is redacted or logs an empty route,
  so a secret path parameter such as the password-reset token never reaches a
  trace or log. `telemetry.Debug`, `Info`, `Warn`, and `Error` fall back to
  `slog.Default()` when the context carries no telemetry.
- The Vite asset check uses the routing subtree accessor
  (`Route.InSubtree`) instead of rebuilding the subtree from the route pattern
  string, so a later pattern change cannot silently widen the CORS or CSRF
  skip.

## CLI

- `new` documents one setup sequence and supports explicit harness selection.
  Commit the selected package-manager lockfile and installed project skill;
  use frozen installation in CI. Creation remains offline-friendly.
- `doctor` validates the generated application's runtime configuration and
  performs a bounded read-only database check. Prerelease lookup results and
  network errors have distinct messages. `verify` reports incomplete setup
  separately from generated-code drift.
- Read-only `inspect pages`, `inspect process`, and `inspect urls` expose
  application structure, prerequisites, and configured host origins. Package
  listings include responsibilities.
- JSON and jq capabilities are registered and checked independently.
  `inspect config --jq .keys` works; unknown group subcommands fail with a usage
  error instead of silently showing successful help.
- Migration-file creation no longer requires a configured or reachable DB.
- `verify` supports stage selection (`--only`), rule selection (`--rules`), and
  changed-file scope (`--changed` with `--base`). Go tests remain opt-in with
  `--with-tests`; reports include per-package outcomes and retain explicit skips.
- Project-declared content invariants validate catalogs, slugs, required files,
  and local links. No configured content means not applicable, not checked.
  See [Content verification](../content-verification.md).
- Frontend verification detects eager full-URL route-helper evaluation, including
  common aliases and immediately invoked functions. Runtime host isolation is
  still necessary; static analysis is not a proof of arbitrary JavaScript.
- `build --output-dir <dir>` stages build inputs and isolates generated assets
  and binaries. Publication preserves previous successful outputs on failure
  and repairs interrupted publication on the next run.
- `ports launch` supervises a child under a loopback-port lease and publishes
  matching SSR listen/URL values only after health and socket-ownership checks.
  Ownership proof currently requires Linux; other platforms fail closed and
  should run the sidecar directly with an explicit fixed listen address.
- `inspect upgrade-notes --from <version>` re-shows manual upgrade actions.
  Structured upgrade dry runs include manifest changes and useful diffs.
- `inspect handlers` follows host-bound router locals (`admin := rt.Host(...);
  admin.Get(...)`) and reports each route's host.
- The `db-handle` rule flags SQL methods (`Exec`, `Query`, `QueryRow`, and
  related surface) called on any `pkg/storage` interface value outside
  `domains/**`; the diagnostic points at the intended test seam.
- `verify --json` always includes `skipped_packages` and `skipped_tests` on the
  `go test` step, empty when nothing was skipped. Every JSON envelope carries
  `cli_version`, and the stdout/stderr contract is documented per exit status:
  a passing run writes its success envelope to stdout, while a failed
  verification exits 9 and writes the error envelope to stderr.
- `doctor` reports the applied, not-applied, or not-applicable state of each
  application-owned manual upgrade action by stable ID. `inspect upgrade-notes`
  re-shows the instructions.
- The method-not-allowed guidance covers JSON error handlers: they must map
  `anduin.ErrMethodNotAllowed` to status 405 and preserve the `Allow` header.
  A framework test covers a custom JSON `ErrorHandler` receiving the error.
- narsilc honours `AS` aliases on joined columns for tags and scan columns and
  fails generation on duplicate tags. `NOT NULL` params are typed non-null, and
  `$1::bigint` keeps a meaningful parameter name (`@name::type` and
  `-- @param` are also accepted).

## Existing applications

Application-owned code is not rewritten automatically. Upgrading to this
release reports these manual actions:

| ID | Required review |
| --- | --- |
| `public-home-v2.0.0-beta.4` | Remove authentication middleware from the welcome route only. |
| `configcheck-v2.0.0-beta.4` | Add the generated read-only configuration-check helper. |
| `runtime-readiness-v2.0.0-beta.4` | Wire database/SSR readiness and expose `/api/ready`. |
| `inertia-ssr-default-v2.0.0-beta.4` | Adopt production SSR defaults and nonrecursive themed error handling. |
| `routes-host-scope-v2.0.0-beta.4` | Regenerate route helpers and adopt render-scoped SSR host configuration. |

Each action explains when an existing application-specific fix is equivalent.
Alpha.4 applications may also need to rename the duplicate `PasswordUpdate`
route from `users.user_password` to `users.update_user_password` before running
`andurel sync routes`; the route-host action includes this prerequisite.
Review production environment overrides explicitly: do not accidentally retain
an `INERTIA_SSR_FAIL_FAST=false` override when SSR is required. Analytics and
site-specific content configuration belong to the application, not the scaffold.

The `app/`, `payloads/`, and `cmd/configcheck` layout, the generated payload
types, and the route-pattern logging changes are defaults for new applications.
No manual action rewrites an existing application's composition root, handler
payload structs, or logging; copy the new shape from a fresh `andurel new` if
you want it. The beta.4 static checks flag the transitions they can prove
(`db-handle`, `payloads-import`, transaction escape) but do not force a layout
change.

## Package changes

- `pkg/routing` adds `Route.Prefix()` and `Route.InSubtree(path)` for route
  subtree checks without pattern string surgery.
- `pkg/storage` adds `RunMigrationsTo` and `AtomicOps` transaction options
  (`ReadOnly()`, `Isolation(...)`), including read-only and repeatable-read
  transactions. `pkg/storage/storagetest` can create a database at a migration
  version and continue migrating it, and provides fault-injecting transactors
  that fail the Nth statement so rollback tests assert the real outcome.
- `pkg/auth` adds capability-token helpers: prefixed URL-safe tokens with at
  least 128 bits of entropy, an eight-character display prefix, and constant-time
  SHA-256 hash verification.
- `pkg/validation` adds `TimeBetween(field, value, now, min, max)` with an
  explicit `now`, so expiry boundaries are deterministic and testable without
  the wall clock.
- `pkg/telemetry`, `pkg/anduin`, and `pkg/inertia` keep raw paths and query
  strings out of spans, metrics, and logs, and fall back to `slog.Default()`
  when no telemetry is attached.
- The testing skill covers the race detector (cgo plus a C compiler, including
  a Zig `CC`), deterministic clocks, real-PostgreSQL test databases, rollback
  fault injection, and read-only or isolated transactions.

## Package versions

`pkg/inertia v0.13.0` adds renderer-wide SSR defaults, page CSR overrides,
bounded readiness checks, and a safe nonrecursive error fallback. The routing,
storage, auth, validation, telemetry, anduin, and inertia APIs described above
ship as standalone module releases with this framework release;
`andurel packages update` resolves the versions published with the release.
