# v2.0.0-beta.4 (candidate)

This is an **unpublished candidate**, not a release announcement. The companion
`pkg/inertia v0.13.0` must be published before the scaffold's candidate pins can
be installed without local replacements. See
`plans/beta3-integration-state.md` for acceptance status and remaining gates.

## Scaffold and runtime

- The welcome page is public; authentication middleware still protects private
  routes.
- Production Inertia pages use the renderer-wide SSR default. `.CSR()` opts a
  page out and `.SSR()` preserves explicit opt-in. Development retains per-page
  SSR. Inertia JSON visits are unaffected.
- `/api/health` is liveness; `/api/ready` checks database and required SSR
  availability. Readiness returns 503 with a stable reason while unavailable
  and recovers when its dependencies recover.
- Error mappings remain client-rendered to avoid recursive SSR failures. The
  scaffold configures its themed error component; the library also provides a
  safe HTML response when no application fallback component is configured.
- Server-side route origins are scoped to each render. Full-URL helpers fail
  clearly before host configuration; `.path()` remains configuration-free.
- The generated SSR executable propagates child failures to its exit status.

## CLI

- `new` documents one setup sequence and supports explicit harness selection.
  Commit the selected package-manager lockfile and installed project skill;
  use frozen installation in CI. Creation remains offline-friendly.
- `doctor` validates the generated application's runtime configuration and
  performs a bounded read-only database check. Prerelease lookup results and
  network errors have distinct messages. `verify` reports incomplete setup
  separately from generated-code drift.
- Read-only `inspect pages`, `inspect process`, and `inspect urls` expose
  application structure, prerequisites, and configured host origins. Package
  listings include responsibilities.
- JSON and jq capabilities are registered and checked independently.
  `inspect config --jq .keys` works; unknown group subcommands fail with a usage
  error instead of silently showing successful help.
- Migration-file creation no longer requires a configured or reachable DB.
- `verify` supports stage selection (`--only`), rule selection (`--rules`), and
  changed-file scope (`--changed` with `--base`). Go tests remain opt-in with
  `--with-tests`; reports include per-package outcomes and retain explicit skips.
- Project-declared content invariants validate catalogs, slugs, required files,
  and local links. No configured content means not applicable, not checked.
  See [Content verification](../content-verification.md).
- Frontend verification detects eager full-URL route-helper evaluation, including
  common aliases and immediately invoked functions. Runtime host isolation is
  still necessary; static analysis is not a proof of arbitrary JavaScript.
- `build --output-dir <dir>` stages build inputs and isolates generated assets
  and binaries. Publication preserves previous successful outputs on failure
  and repairs interrupted publication on the next run.
- `ports launch` supervises a child under a loopback-port lease and publishes
  matching SSR listen/URL values only after health and socket-ownership checks.
  Ownership proof currently requires Linux; other platforms fail closed and
  should run the sidecar directly with an explicit fixed listen address.
- `inspect upgrade-notes --from <version>` re-shows manual upgrade actions.
  Structured upgrade dry runs include manifest changes and useful diffs.

## Existing applications

Application-owned code is not rewritten automatically. Upgrading to this
candidate reports these manual actions:

| ID | Required review |
| --- | --- |
| `public-home-v2.0.0-beta.4` | Remove authentication middleware from the welcome route only. |
| `configcheck-v2.0.0-beta.4` | Add the generated read-only configuration-check helper. |
| `runtime-readiness-v2.0.0-beta.4` | Wire database/SSR readiness and expose `/api/ready`. |
| `inertia-ssr-default-v2.0.0-beta.4` | Adopt production SSR defaults and nonrecursive themed error handling. |
| `routes-host-scope-v2.0.0-beta.4` | Regenerate route helpers and adopt render-scoped SSR host configuration. |

Each action explains when an existing application-specific fix is equivalent.
Alpha.4 applications may also need to rename the duplicate `PasswordUpdate`
route from `users.user_password` to `users.update_user_password` before running
`andurel sync routes`; the route-host action includes this prerequisite.
Review production environment overrides explicitly: do not accidentally retain
an `INERTIA_SSR_FAIL_FAST=false` override when SSR is required. Analytics and
site-specific content configuration belong to the application, not the scaffold.

## Release gate

Only `pkg/inertia` changes its standalone module version, to candidate
`v0.13.0`; other package pins remain as in beta.3. Development validation with
local replacements or the isolated golden-test module proxy is **not** proof
of published-module installation. Publication, a fresh release-shaped scaffold,
and the outstanding acceptance gates must precede a release announcement.
