# v2.0.0-beta.7

Serving several domains from one app is now explicit: routes register on the
host they declare, each domain states what happens to paths it does not match,
and per-domain middleware is a host option. A bare `/` route no longer catches
every path, which is a breaking change for single-page-app fallbacks.

The generated login and token code also closes three races and one error case:
a password reset could be undone by a sign-in that was already in progress,
two password reset or verification codes could be live at once, and a user
without a password got a hash-format error instead of "invalid email or
password".

## Login and token fixes

- `RehashPassword` takes the stored hash that the password was verified
  against. It saves the new hash only if the locked row still holds that hash.
  A password changed after the sign-in read the user keeps its new password.
- Replacing a user's token locks the user's row first, so concurrent requests
  run one after another. Before, both could delete the old token and insert a
  new one, leaving two live codes.
- `AuthenticateUser` rejects a user with an empty stored password with
  `ErrInvalidCredentials` after the same dummy hash work as an unknown email.
- The token queries gain `LockTokenOwner`.

## Existing applications: login and tokens

Application-owned code is not rewritten automatically. The changes below are
for applications generated before this release. Apply them by hand, or leave
the code as it is if you do not need the fixes.

### Password rehash race

`domains/user.go`, the signature and the locked-row check:

```go
// Before
func (u Users) RehashPassword(
	ctx context.Context,
	pepper string,
	id uuid.UUID,
	password string,
) (User, error) {
	// ...
		locked, err := users.FindForUpdate(ctx, id)
		if err != nil {
			return err
		}

		locked.Password = []byte(hashedPassword)
		entity, err = users.Save(ctx, locked)
	// ...
}

// After
func (u Users) RehashPassword(
	ctx context.Context,
	pepper string,
	id uuid.UUID,
	verifiedHash []byte,
	password string,
) (User, error) {
	// ...
		locked, err := users.FindForUpdate(ctx, id)
		if err != nil {
			return err
		}
		if !bytes.Equal(locked.Password, verifiedHash) {
			entity = locked

			return nil
		}

		locked.Password = []byte(hashedPassword)
		entity, err = users.Save(ctx, locked)
	// ...
}
```

Add `"bytes"` to the imports of `domains/user.go`.

`services/authentication.go`, the call site:

```go
// Before
user, err = i.users.RehashPassword(ctx, i.pepper, user.ID, data.Password)

// After
user, err = i.users.RehashPassword(ctx, i.pepper, user.ID, user.Password, data.Password)
```

## Breaking

- **A route on `/` matches only `/`.** Before, a bare `/` was a subtree pattern
  and caught every path on every host. A catch-all must now be `/*`:

  ```go
  // before: caught every path
  var SPA = routing.NewSimpleRoute("/", "spa", "")

  // after: explicit catch-all
  var SPA = routing.NewSimpleRoute("/*", "spa", "")
  ```

  `routing.Exact()` on `/` is a no-op and can be deleted.

- **`middleware.AuthOnly` takes the hosts.** A visitor rejected on a secondary
  host is sent to the primary host's sign-in page as an absolute URL, which needs
  the registry:

  ```go
  // before
  rt.Get(routes.Dashboard.Pattern(), h.Dashboard, middleware.AuthOnly(users))

  // after
  rt.Route(routes.Dashboard).Get(h.Dashboard, middleware.AuthOnly(users, hosts))
  ```

## Routes and hosts

- **Register routes with `rt.Route(route)`.** The route value decides the host.
  `rt.Get(routes.AdminDashboard.Pattern(), h)` serves an admin route on the
  primary host; the form below serves it on the admin host.

  ```go
  // before: served on the primary host, whatever host the route declares
  rt.Get(routes.AdminDashboard.Pattern(), h.Dashboard)

  // after: served on the host declared with routing.Host(config.HostAdmin)
  rt.Route(routes.AdminDashboard).Get(h.Dashboard)
  ```

  `rt.Host(name).Route(route)` does the same on a named host and panics when the
  route declares a different host. `rt.Get(path, ...)` stays for ad-hoc routes.

- **Every host with routes states a fallback policy.** Without one,
  `router.Handler()` panics at boot, so the choice cannot be missed:

  ```go
  admin := rt.Host(config.HostAdmin)
  admin.FallbackToPrimary() // unmatched paths use the primary site's routes
  // or
  admin.Isolate()           // unmatched paths answer 404 on this domain
  ```

  `FallbackToPrimary` means assets and `robots.txt` work on the admin domain
  without being registered twice. A host with no routes needs no call.

- **Per-domain middleware.** `Host.Use` runs after global middleware and before
  per-route middleware, only for requests the host answers from its own routes:

  ```go
  // before: a global middleware checked the host and kept a list of exempt paths
  router.Use(requireAdminHost(config.HostAdmin, exemptPaths))

  // after
  admin := rt.Host(config.HostAdmin)
  admin.Use(middleware.AuthOnly(users, hosts))
  ```

- **`Host.Mount(prefix, handler)`** mounts any `http.Handler` (for example River
  UI) on a host for every method, and **`anduin.SkipCSRFForHosts(names...)`** is a
  CSRF skipper for named hosts.

- **Sign-in is absolute across hosts.** Auth rejections on a secondary host
  redirect to `https://example.com/users/sign-in` rather than a path the host may
  not serve.

- **Safe "return to" redirects.** `anduin.SafeLocalPath(target)` reports whether a
  redirect target is a path on this site; `anduin.RedirectLocal(ctx, target,
  fallback, status)` redirects there and falls back otherwise. Use them instead of
  redirecting to a raw query parameter.

## Configuration

- **`HOST_<NAME>` for extra hosts.** Declare the host in `config/hosts.go` and list
  it in `extraHostNames`:

  ```go
  // config/hosts.go
  const HostAdmin routing.HostName = "admin"

  var extraHostNames = []routing.HostName{HostAdmin}
  ```

  `config.NewApp` reads `HOST_ADMIN`. When it is unset the host defaults to
  `admin.` followed by `HOST_PRIMARY` (for example `admin.localhost:8080` in
  development). Every domain is validated with the rest of the configuration, so
  a bad extra domain fails at config load, not at startup. Nothing is added to
  `App.Hosts` unless a name is listed, so existing apps keep their host set.

- **`SESSION_COOKIE_DOMAIN`** sets the `Domain` attribute on the session and CSRF
  cookies. It is empty by default, which keeps one cookie per host. Set it to
  `.example.com` to share a sign-in across subdomains. A value with a scheme,
  path or port fails config validation.

## CLI

- **`andurel verify` rule `route-host`.** It flags `rt.Get(routes.X.Pattern(), ...)`
  (and the other registration methods, on the router or a host) when route `X`
  declares a non-primary host. The fix is `rt.Route(routes.X).Get(...)`.
- **`andurel inspect urls` resolves extra hosts the way the app does.** An unset
  `HOST_<NAME>` defaults to `<name>.` + `HOST_PRIMARY` instead of being reported
  unresolved.
- **Full-URL TypeScript helpers match Go for unconfigured hosts.** A helper for a
  host with no configured origin returns the path, as `FullURL` does in Go. It
  previously fell back to the primary origin. The reproduction: with origins
  `{ primary: 'https://example.com' }`, `routes.widgetIndex()` for a route on
  `admin` returned `https://example.com/widgets` and Go returned `/widgets`.

## Existing applications: multiple domains

Application code is not rewritten automatically. To move an existing app:

1. Replace `rt.Get(routes.X.Pattern(), h)` with `rt.Route(routes.X).Get(h)` for
   every route bound to a host with `routing.Host(...)`. `andurel verify` lists
   them under `route-host`.
2. Replace `/` catch-all routes with `/*`, and delete `routing.Exact()`.
3. Give every host that has routes `FallbackToPrimary()` or `Isolate()`.
4. Pass the host registry to `middleware.AuthOnly(users, hosts)`.
5. Move any host check used for per-domain policy into `Host.Use`.
6. To share sessions across subdomains, set `SESSION_COOKIE_DOMAIN` in the
   environment. Leave it unset to keep the current behaviour.
