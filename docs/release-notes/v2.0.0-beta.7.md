# v2.0.0-beta.7

## Routes, hosts and sign-in (#851, #852, #853, #854)

- Routes register on their declared host with `rt.Route(route)`. A host with
  routes must choose `FallbackToPrimary()` or `Isolate()`; `Handler()` rejects
  missing policies and routes on unconfigured host names at startup. Host-specific
  middleware, mounts and CSRF exemptions are available. Host middleware passes
  its updated request and context to route and mount dispatch; fallback to the
  primary table bypasses host middleware.
- **Breaking:** A bare `/` previously caught unmatched paths; it now matches
  only the root. `/*` is the explicit catch-all, and `routing.Exact()` remains a
  compatible no-op. `Route.Name()` returns the route name.
  `anduintest.WithRouterOptions` passes router options such as a host registry
  to handler tests.
- Extra `HOST_<NAME>` values are validated as hostnames with optional ports;
  schemes, paths and whitespace are rejected. `inspect urls` resolves defaults
  only for configured host names and marks unknown hosts unresolved.
- `SESSION_COOKIE_DOMAIN` optionally shares session and CSRF cookies across
  subdomains. Auth rejections preserve a safe return destination for signed-out
  GETs in an encrypted cookie; sign-in and email confirmation consume it.
- `Renderer.Redirect` uses a 409 `X-Inertia-Location` response for cross-host
  Inertia redirects. Generated auth rejection uses the same full-visit behavior;
  generated sign-out links use a same-origin path on secondary hosts.

## Login and tokens (#848)

- Password rehashing checks the verified hash under lock, so it cannot overwrite
  a concurrent password reset. When a login needs rehashing, a changed verified
  hash or session version at the locked check also rejects authentication with
  generic invalid credentials, preventing a stale login from obtaining a valid
  post-reset session. Token replacement locks the owner row to prevent
  concurrent live codes. A user with no password receives invalid credentials
  after dummy hash work rather than a hash-format error.

## Tests, diagnostics and scaffold (#849)

- `storagetest` disables Ryuk and labels its containers. Older containers are
  removed only with matching hostname, Linux boot ID and PID namespace and a
  definitely absent owner PID. Legacy labels, unverifiable or different scopes,
  and non-Linux platforms do not qualify. Inspect labelled containers and
  verify their owners are inactive across hosts and PID namespaces before any
  manual removal.
- `QueueInsert.Client()` exposes the queue client. The generated test cookie jar
  registers every app cookie, including return-to and flash cookies.
- `verify` runs independent stages even after failures, scopes generated drift,
  suggests `--only` for scoped generated failures, reports query/migration
  mismatches and directs JSON failure readers to stderr. Scoped domains checks
  load generated query syntax; route and payload scopes include their generated
  TypeScript helpers. Transient build directories are excluded from drift walks.
  `sync queries` uses the same query/migration diagnostic. App startup tests,
  included by `verify --with-tests`, catch missing host fallback policies; plain
  verify does not statically check them.
- Migration generation chooses a version above the newest existing version.
  `db create` reports the underlying error with credentials redacted.
- SSR falls back to client rendering in development and tests when unavailable;
  production remains strict. `/api/health` is liveness, while `/api/ready`
  checks database readiness.
- Before frontend assets are built, the generated app tests that require them
  may skip: `TestViteAssetsUsePublicCORS`, `TestViteAssetsSkipCSRFCookie`,
  `TestReadinessFailsWhenProductionSSRSidecarIsUnavailable`,
  `TestReadinessRecoversWithHealthySSRSidecar`,
  `TestReadinessIgnoresSSRWithExplicitCSRFallback`, and
  `TestInertiaVisitsWithBuiltAssets`. Build the frontend to exercise them.
- Themed error pages map HTTP errors by status and preserve explicitly supplied
  public 4xx messages, without exposing private underlying causes. The
  `test-service` pattern documents its Products prerequisite and module path.
  Scaffold guidance covers cookie domains, testing and patterns;
  the Tailwind source path points to `resources/js` and the obsolete views source
  is gone. An empty default sender setting falls back to the default.
- Migration guidance for existing databases explains retaining River and auth
  migrations and using additive schema changes, or rewriting auth before removing
  its tables. Domain guidance covers nullable SQL filters and read-only joins.
- New patterns cover injected provider HTTP clients with fake transports, staging
  frontend work after Go declarations, and atomic multi-table seeds using shared
  `storage.AtomicOps` and transaction-bound receivers.

## Development runner and assets

- `andurel run` uses an in-process development runner instead of a separately
  installed runner. It watches the root document separately from email compilation,
  preserving compiled email output, and shuts down its child processes on signal.
- The runner preserves the browser's Host when proxying application requests.
  Its development proxy serves Vite modules and fonts on the app origin and
  forwards HMR WebSockets, with host and origin checks, so custom local hosts
  work without a broad Vite CORS workaround.
- Inertia's default asset version derives from the Vite manifest when available,
  with a stable development fallback, so changed builds can trigger client reloads.
