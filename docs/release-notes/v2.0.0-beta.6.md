# v2.0.0-beta.6

Removes the generated `cmd/configcheck` program and the doctor check that ran
it, and drops upgrade notes between pre-releases. No `pkg/*` module changes.

## Scaffold

- `andurel new` no longer generates `cmd/configcheck`. Running the application
  already validates its configuration at startup, so the separate program
  duplicated that check.
- The README and layer-placement guidance no longer mention `configcheck`.

## CLI

- `doctor` no longer runs the "Runtime config" check, which built and ran
  `cmd/configcheck`. It no longer needs a database or a complete `.env` to pass.
- `build` excludes only `cmd/seeds` from the binaries it builds into `dist/`.
- Upgrade notes only exist between proper releases. Alpha and beta releases no
  longer carry manual actions, so `andurel upgrade`, `inspect upgrade-notes`,
  and doctor's "Manual actions" check report none for upgrades between
  pre-releases. The commands stay in place for `v2.0.0` → `v2.x` upgrades.
  Scaffold changes in a pre-release are documented in its release notes with
  before/after code.

## Existing applications

Application-owned code is not rewritten automatically. If your application has
`cmd/configcheck`, delete it:

```bash
rm -rf cmd/configcheck
```

Otherwise `andurel build` now builds it into `dist/` alongside your other
binaries. Nothing else imports it.

## Package versions

No standalone module changes. The `pkg/*` versions published with beta.4
remain current.
