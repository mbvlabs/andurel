# v2.0.0-rc.1

This release replaces the Tailwind email compiler with React Email. Emails are
authored as TSX components and Go data structs in one `emails/` directory,
exported to committed Go `text/template` files in `emails/templates/`, and
rendered by Go at send time. Sending, MIME, SMTP, Mailpit and River workers are
unchanged. The app-facing email module `pkg/email` is removed and replaced by
`pkg/postmand`, which now also owns the Go template renderer. `pkg/inertia`
moves to v0.15.0 for the standard-library root document.

## Breaking: email compiler removed

The old pipeline authored email as templ, compiled Tailwind at build time and
inlined a subset of utilities into `email/*_templ.go`. It is gone:
`emailcompiler/`, `andurel sync email`, `css/email.css`, `email/*.templ`, the
separate email watcher, and doctor/verify's old email drift owner are all
removed. templ is not used at all in this release (see "Breaking: templ
removed" below).

Why:

- Tailwind v4 writes `px-*` as `padding-inline` and `py-*` as `padding-block`.
  Gmail, classic Outlook and Yahoo drop logical properties, so the scaffolded
  emails lost their 48px side gutters, the code box lost its padding, and the
  password-reset button rendered as a thin strip.
- Tailwind's oklch theme values and `var()` references are unsupported by
  Gmail, classic Outlook and Yahoo; some clients strip an element's entire
  `style` attribute when they see modern color syntax.
- The supported utility subset was invisible. Dynamic and conditional classes
  were rejected, unknown classes passed through silently, two generators
  produced one file type, and there was no way to see an email without
  sending it.

Email is now React Email 6.11.6 with style objects and hex tokens from
`emails/theme.ts`. React Email is the best-known email library for agents, the
props are typed from the Go structs, and `andurel email render --watch --open`
gives a live visual design loop. The shared `Layout` emits color-scheme metas
and a
`prefers-color-scheme: dark` block with `[data-ogsc]`/`[data-ogsb]` selectors;
that block is a progressive enhancement for Apple Mail and Outlook.com, and the
light hex palette stays inline for every other client.

### What's new

- `emails/` is the only email directory. It holds the authored TSX
  (`theme.ts`, `components/layout.tsx`, `components/code-box.tsx`, one
  `<kebab>.tsx` per email, `export.tsx`, `tsconfig.json`) next to the Go
  package `emails` (`render.go`, one `<snake>.go` per email, `previews.go`) and
  the committed `templates/*.tmpl`. Go ignores `.tsx`/`.ts` files and the
  `components/` and `generated/` directories because they hold no Go files, so
  both languages share one tree.
  `emails/generated/{props,manifest}.ts` is generated and committed.
- `emails/render.go` embeds `emails/templates/*.tmpl` and renders them with
  `postmand.Templates` from `github.com/mbvlabs/andurel/pkg/postmand`; HTML
  placeholders are `{{.Field | html}}` and text placeholders are `{{.Field}}`.
  The renderer uses `text/template` on purpose because `html/template` strips
  the `<!--[if mso]>` conditionals React Email emits for Outlook.
- `andurel sync emails [--skip-export] [--json]` scans exported structs in
  `emails/*.go` that declare `ToHTML`, writes `emails/generated/props.ts` and
  `manifest.ts`, then runs the project's `email:export` script to write
  `emails/templates/*`.
- `andurel email render [name] [--json] [--open] [--watch]` runs
  `go run ./cmd/emails`, which renders `emails.Previews()` through the real
  `ToHTML`/`ToText` path into `tmp/emails/<name>.html`,
  `tmp/emails/<name>.txt` and an `index.html` gallery with desktop (600px),
  mobile (375px), dark (600px) and text panes. `--watch` reruns the sync and
  export on `emails/**` changes and reloads the gallery over `file://`;
  `--json` and `--watch` cannot be combined. It sends nothing.
- `andurel build` and `andurel run` run `andurel sync emails` and the export
  automatically before compiling or rebuilding. `cmd/emails` is excluded from
  `andurel build` and is never deployed.
- `andurel doctor` reports drift as the `emails export` check; `andurel verify`
  maps the generated props, manifest and templates to `andurel sync emails`.
- `github.com/mbvlabs/andurel/pkg/email` is removed. Applications use
  `github.com/mbvlabs/andurel/pkg/postmand` instead; there is no `pkg/email`
  v0.7.0 release. The old and new data types are intentionally not compatible,
  so update every import before building against `pkg/storage v0.16.0`.

## Breaking: templ removed

templ is no longer part of Andurel. The Inertia root document is now a
standard-library `html/template` file rendered by `resources/root.go`, and
`github.com/a-h/templ` is removed from generated `go.mod`, `andurel.lock`,
`andurel.toml`, the managed tool list, `andurel build`, `andurel fmt`,
`andurel doctor`, and `andurel run`. `andurel fmt --skip-templ` is gone; use
`andurel fmt --skip-go` when you only need the remaining formatters.

`pkg/inertia` v0.15.0 is the matching release: `WithRoot` renders the new
`html/template` root, the old component helpers are gone, and `RootData` adds
`.PageScript`, `.AppMount`, `.SSRHead`, and `.SSRBody` methods that return safe
`template.HTML` fragments. A compiled templ root is deliberately not
compatible: follow the migration below.

### Migrate an existing project

`andurel upgrade` leaves the application-owned root document untouched, so an
upgraded beta project does not compile until you complete this manual step. The
upgrade reports it as the `templ-root-v2.0.0-rc.1` manual action when the
project still has `resources/root.templ` or `resources/root_templ.go`; it never
rewrites those files.

1. Replace `resources/root.templ` and `resources/root_templ.go` with
   `resources/root.html`:

   ```html
   <!doctype html><html lang="en"><head><meta charset="utf-8"><meta name="viewport" content="width=device-width, initial-scale=1">{{if not .SSR}}<title>{{.ProjectName}}</title>{{end}}{{.SSRHead}}{{.ViteHead}}</head><body class="bg-background text-foreground">{{if .SSR}}{{.SSRBody}}{{else}}{{.PageScript}} {{.AppMount}}{{end}}{{.ViteBody}}</body></html>
   ```

   and `resources/root.go`:

   ```go
   package resources

   import (
       "embed"
       "html/template"
   )

   //go:embed root.html
   var files embed.FS

   // Root is the Inertia root document rendered with html/template.
   var Root = template.Must(template.New("root.html").ParseFS(files, "root.html"))
   ```

   `config/inertia.go` keeps `inertia.WithRoot(resources.Root)`. Keep
   `{{.PageScript}}`, `{{.AppMount}}`, `{{.SSRHead}}`, `{{.SSRBody}}`,
   `{{.ViteHead}}`, and `{{.ViteBody}}` unescaped: they are pre-rendered and
   already escaped safe fragments.

2. Bump the renderer module and regenerate dependencies:

   ```bash
   go get github.com/mbvlabs/andurel/pkg/inertia@v0.15.0
   go mod tidy
   ```

3. Remove templ from the `go.mod` tool directive:

   ```diff
    tool (
   -    github.com/a-h/templ/cmd/templ
    )
   ```

   `andurel upgrade` drops the matching tool entry from `andurel.lock` and the
   templ tool directive from `go.mod` automatically. It never fails on the
   legacy tool. If you are editing by hand, also delete `templ` from the
   `[tools]` section of `andurel.toml`, the templ hash entries in
   `andurel.lock`, `bin/templ`, and `tmp/templ`.

4. Run `andurel doctor`, `andurel build`, and `andurel verify`. No templ check
   runs, and `resources/root.html` is validated by compiling
   `resources/root.go`.

## Migrating a beta project

`andurel upgrade` does not rewrite application-owned email code. Create one
reference project with the same adapter and package manager as yours, then copy
the infrastructure and port the templates.

```bash
# Same --ui value as your project. For example:
andurel new email-reference --ui react/pnpm
```

### 1. Copy the new email tree

From the reference project, copy the whole `emails/` directory: `theme.ts`,
`components/`, `export.tsx`, `tsconfig.json`, `generated/`, the Go files
(`render.go`, `previews.go`, `verify_email.go`, `reset_password.go`) and
`templates/`. Also copy `cmd/emails/`.

```bash
mkdir -p emails cmd/emails
cp -R ../email-reference/emails .
cp -R ../email-reference/cmd/emails cmd/
```

If you deleted or renamed the scaffold's `VerifyEmail` or `ResetPassword`, also
delete the matching sample components (`emails/verify-email.tsx`,
`emails/reset-password.tsx`), sample Go files and sample templates; `andurel
sync emails` regenerates the templates for the structs you actually keep.

### 2. Add the frontend dependencies and scripts

In `package.json`, add the React Email dev dependencies. React projects already
have `react`/`react-dom` in `dependencies`; Vue and Svelte projects need them in
`devDependencies` too.

```json
{
  "devDependencies": {
    "react-email": "6.11.6",
    "tsx": "4.23.15",
    "@types/node": "^22.0.0",
    "@types/react": "^19.0.0"
  }
}
```

```json
{
  "devDependencies": {
    "react": "^19.0.0",
    "react-dom": "^19.0.0"
  }
}
```

Add the export script and extend the existing `typecheck` script so `emails/`
is covered:

```json
{
  "scripts": {
    "email:export": "tsx --tsconfig emails/tsconfig.json emails/export.tsx",
    "typecheck": "tsc --noEmit && tsc -p emails/tsconfig.json"
  }
}
```

Keep your adapter's existing typecheck command and append
`&& tsc -p emails/tsconfig.json`:

```json
"typecheck": "vue-tsc --noEmit && tsc -p emails/tsconfig.json"
"typecheck": "svelte-check && tsc -p emails/tsconfig.json"
```

`emails/tsconfig.json` comes from the copy in step 1. The Vite build does not
include `emails/`.

### 3. Move your own Go email code into `emails/`

Every existing Go email file moves from `email/` to `emails/`, the package
clause becomes `package emails`, and every import of `<module>/email` becomes
`<module>/emails` (replace `<module>` with the module path in `go.mod`). The
scaffold imports the package without an alias: `<module>/emails` and `emails.`.

```bash
mkdir -p emails/templates
if ls email/*.go >/dev/null 2>&1; then git mv email/*.go emails/; fi
if ls email/templates/*.tmpl >/dev/null 2>&1; then
  git mv email/templates/*.tmpl emails/templates/
fi
if ls emails/*.go >/dev/null 2>&1; then
  sed -i 's/^package email$/package emails/' emails/*.go
fi
grep -rl '"<module>/email"' --include='*.go' . |
  xargs -r sed -i 's|"<module>/email"|"<module>/emails"|g'
```

Update the imports in the same files: `<module>/emails` is imported without an
alias and its uses become `emails.`. Replace any scaffold alias from earlier
releases (`appemail` or `appemails`) with `emails.`. Search for any remaining
imports:

```bash
grep -rn '"<module>/email"' --include='*.go' .
```

Delete the old directory once it is empty:

```bash
rmdir email 2>/dev/null || true
```

If your project already has both `email/` and `emails/` from an rc preview, the
same `git mv` steps move the Go package and templates into the existing tree.

### 4. Replace `pkg/email` with `pkg/postmand` (breaking)

`github.com/mbvlabs/andurel/pkg/email` is removed in rc.1; it is not renamed to
a deprecated module and there is no `pkg/email v0.7.0`. Generated apps now
require `github.com/mbvlabs/andurel/pkg/postmand`. A `pkg/storage` pin older
than `v0.16.0` still exposes `pkg/email` types in
`SendTransactionalEmailArgs`, `AddEmailWorkers`, and the worker sender fields,
so leaving either module at its old version does not compile after the import
change. `andurel upgrade` reports this as the `postmand-v2.0.0-rc.1` manual
action when the project still requires or imports `pkg/email`; it never
rewrites application email code. Upgrade both modules first, in this order:

```bash
go get github.com/mbvlabs/andurel/pkg/postmand@v0.1.0
go get github.com/mbvlabs/andurel/pkg/storage@v0.16.0
```

Then replace the imports:

```bash
grep -rl 'github.com/mbvlabs/andurel/pkg/email' --include='*.go' . |
  xargs -r sed -i 's|github.com/mbvlabs/andurel/pkg/email|github.com/mbvlabs/andurel/pkg/postmand|g'
(cd <module> && go mod edit -droprequire github.com/mbvlabs/andurel/pkg/email)
```

Remove the `pkgemail` alias while you are there: import
`"github.com/mbvlabs/andurel/pkg/postmand"` and use `postmand.Transformer`,
`postmand.Compose` and `postmand.TransactionalData`.

The template renderer also moved out of `emails/`. Replace `emails/render.go`
with the reference project's small file:

```go
package emails

import (
	"embed"

	"github.com/mbvlabs/andurel/pkg/postmand"
)

// templates holds the React Email export (see export.tsx). Regenerate with
// `andurel sync emails`.
//
//go:embed templates/*.tmpl
var templatesFS embed.FS

var templates = postmand.MustParseTemplates(templatesFS, "templates")
```

Then replace `renderHTML("name", v)` with `templates.HTML("name", v)` and
`renderText("name", v)` with `templates.Text("name", v)` in each email struct.

After the imports and renderer are updated, run `go mod tidy` to remove the
obsolete `pkg/email` requirement and record the upgraded module checksums:

```bash
go mod tidy
```

Do not tidy before upgrading `pkg/storage`: storage older than `v0.16.0` still
requires `pkg/email`, and mixing its `pkg/email` worker types with postmand
service types does not compile.

### 5. Port each `email/*.templ`

For every email, keep the Go struct and its fields, replace the templ renderer
with `templates.HTML`/`templates.Text`, and write the markup as a React Email
component.

```go
// emails/welcome_email.go
package emails

type WelcomeEmail struct {
    UserName string
}

func (w WelcomeEmail) ToHTML() (string, error) { return templates.HTML("welcome_email", w) }
func (w WelcomeEmail) ToText() (string, error) { return templates.Text("welcome_email", w) }
```

```tsx
// emails/welcome-email.tsx
import { Heading, Section, Text } from "react-email"
import { Layout } from "./components/layout"
import type { WelcomeEmailProps } from "./generated/props"
import { theme } from "./theme"

export default function WelcomeEmail({ UserName }: WelcomeEmailProps) {
  return (
    <Layout title="Welcome" preview="Thanks for joining us.">
      <Section className="email-px" style={{ padding: "48px 48px 24px 48px" }}>
        <Heading
          as="h1"
          className="email-fg"
          style={{ color: theme.foreground, fontSize: 30, margin: 0 }}
        >
          Welcome, {UserName}!
        </Heading>
        <Text
          className="email-fg"
          style={{ color: theme.foreground, fontSize: 16 }}
        >
          Thank you for joining us.
        </Text>
      </Section>
    </Layout>
  )
}
```

Rules while porting:

- Keep the Go type name: `WelcomeEmail` becomes `emails/welcome_email.go`,
  template name `welcome_email`, and component `emails/welcome-email.tsx`.
- Use `Layout` and the `theme.ts` hex tokens. Never add `<Tailwind>`, logical
  padding (`padding-inline`, `padding-block`, `margin-inline`), `oklch()`,
  `var()`, or a literal `{{` in TSX or CSS.
- Scalar fields only (`string`, integer kinds, `float64`). Format lists and
  optional text into a string field in Go before rendering.
- Render every field in both the HTML and text output; `email:export` fails if a
  prop is missing from the rendered output.

### 6. Delete the old email files

```bash
rm email/*.templ email/*_templ.go css/email.css
rmdir email 2>/dev/null || true
```

Remove any `email/` references from your own build scripts. The `andurel`
CLI's build, run and doctor commands handle the new export; no project-local
Tailwind email input is needed. Do not run `templ generate` for `emails/`; the
Go files there are plain Go, and the TSX is not templ.

### 7. Add a Preview entry per email

`andurel email render` reads `emails/previews.go` only. Add one typed entry per
email; a renamed Go field is a compile error.

```go
func Previews() []Preview {
    return []Preview{
        {
            Name:    "welcome_email",
            Subject: "Welcome",
            Email:   WelcomeEmail{UserName: "Ada"},
        },
    }
}
```

### 8. Install, regenerate and verify

```bash
pnpm install                    # or npm install / bun install
andurel sync emails             # writes emails/generated and emails/templates
andurel email render --json     # renders through the real Go path
andurel email render --open     # optional: gallery at tmp/emails/index.html
andurel doctor
```

`andurel sync emails` needs installed frontend dependencies because
`email:export` imports `react-email` and `tsx`. Use `--skip-export` only when
you need the generated props without the templates. Commit `emails/` and
`package.json` together.

For a visual design loop while porting, run
`andurel email render --watch --open` and edit the components and templates; the
gallery reloads itself and always renders the real Go substitution.

## Command changes

| Old | New |
| --- | --- |
| `andurel sync email` | `andurel sync emails` (`--skip-export`, `--json`) |
| — | `andurel email render [name] [--json] [--open] [--watch]` |
| `emailcompiler` and `css/email.css` | `emails/*.tsx` + `emails/theme.ts` |
| `email/*.templ` + `email/*_templ.go` | `emails/*.go` + `emails/templates/*.tmpl` |
| `resources/root.templ` + `root_templ.go` | `resources/root.html` + `resources/root.go` |
| `templ generate` in build/doctor/run | plain `go build`; `resources/*.html` is watched |
| `andurel fmt --skip-templ` | removed; use `andurel fmt --skip-go` |

`andurel patterns show email` documents the full authoring loop, component
catalog and checklist.
