## B7-002 — narsilc runtime skew is explicit

- `andurel tool set-version narsilc <version>` continues to update only the tool
  configuration, lock file and installed binary. It never edits `go.mod` or
  `go.sum`, and it does not install a runtime requirement that is absent.
- After a successful tool update, it reads the
  `github.com/mbvlabs/narsilc` requirement from `go.mod` using the Go module
  parser and semver helpers. It reports `aligned`, `mismatch`, `missing`,
  `replaced` or `unverifiable`; a replacement, unreadable or malformed module
  data is never reported as aligned.
- A mismatch prints the exact remediation:
  `go get github.com/mbvlabs/narsilc@<version>` followed by `go mod tidy`.
  Structured output carries the same result in `narsilc_runtime`, `warnings`
  and `next_steps`.
- `andurel doctor` now has a `narsilc runtime` check on both human and
  structured surfaces. A mismatch is a warning with the actionable commands; a
  missing requirement is reported as not required, not as aligned.
- Install/config failure is reported as a failure and does not emit runtime
  guidance. Equal and mismatched versions, missing requirements, local and
  versioned replacements, unavailable module data, unrelated tools, invalid
  versions and failed set-version operations are covered by focused tests.

## B7-005 — middleware error context is preserved

### Global and host errors render at the failing boundary

- Errors from global and host middleware now render at the failing boundary,
  before enclosing middleware unwinds. `ErrorHandler` receives the context
  actually passed to the failing layer, so middleware values such as the kiks
  bag/session are present.
- Enclosing middleware resources and a live request context are available
  during the render. Kiks-style response writers observe the final error status,
  so 409 flashes, 303 redirects, 403 flash clears and dirty-session persistence
  behave at the intended time.
- The failing middleware's own deferred resources may already have unwound;
  only middleware still enclosing the failing boundary is guaranteed live.

### Route and handler errors keep the delayed contract

- Route middleware and handlers still render after route middleware unwinds.
  Existing route consumers such as `APIDocumentationErrors` continue to return
  their own response and prevent a router render.
- Delayed scopes retain the deepest middleware values from the latest failing
  pass. A later retry that succeeds renders nothing; fail/fail uses the latest
  failing attribution.
- Delayed scopes merge recorded values with the live request. The first
  cancellation classification is frozen: an expired deadline reports
  `context.DeadlineExceeded` with its custom cause, explicit cancellation or
  cleanup reports `context.Canceled`, cleanup before a later deadline stays
  `Canceled`, and derived `WithCancel`/`WithCancelCause` children inherit the
  same classification. A canceled child context no longer leaks cancellation
  into the `ErrorHandler`, deep nil value masks remain stable, and no deadline
  timer is recreated.
- Route-scope resources are not guaranteed live after route middleware returns.
  Error providers must not assume released transactions, connections or locks
  are still usable.

### `CatchErrors` is the explicit compatibility point

- Global or host middleware that consumes, translates or retries an error must
  wrap its layer with `CatchErrors`. Without it, the inner guard renders before
  the outer middleware sees the error.
- `CatchErrors` propagates the original error unchanged, returns nil only when
  the wrapped middleware consumes it, and renders once at scope exit with the
  latest failing pass's deepest values. It merges recorded values with the live
  request context and does not invoke the `ErrorHandler` when the final error is
  nil.
- Nested delayed scopes hand their failing attribution to the enclosing scope
  instead of rendering first, so the outer owner can consume, translate or
  retry before the single commit.
- Route middleware keeps the implicit delayed scope and needs no change.

### Error lifecycle API

- `RenderedError(ctx)` reports the error already rendered on the request. A
  coordinating response capture can use it to commit the captured error page.
- `ResponseBuffer` with `DiscardBuffered()` lets a capture drop buffered
  successful content before the error page is written. The router walks the
  response-writer `Unwrap` chain and calls it before invoking the
  `ErrorHandler`.
- `ErrResponseCommitted` and `CommittedError` make once-only rendering
  observable. A retry after an early render returns `ErrResponseCommitted`
  through the committed wrapper; the original rendered error remains available
  through `errors.Is`/`errors.As`.

### Inertia capture coordination

- Inertia now commits a router-rendered error page instead of discarding it.
  Buffered success status, body and response-owned headers are discarded before
  the error page; `Allow`, `Vary`, security/CORS policy and standard
  authentication/retry metadata survive the replacement.
- A rendered redirect still commits its normalized response when reflash fails.
  The original, reflash and commit errors are joined without invoking the error
  handler again.
- An old inertia capture without `ResponseBuffer` is detected as a mixed
  new-anduin/old-inertia deployment. The router discards the captured page and
  answers with one safe plain 500; it does not produce a themed error or invoke
  `ErrorHandler` twice. Update anduin and inertia together before claiming
  end-to-end themed host/global error support.

### Mux and B7-007 ordering

- ServeMux-generated 404/405 errors now travel through the host/global
  boundary, so `CatchErrors` can consume or translate them. `Allow` is preserved
  across a capture discard, and fallback-to-primary behavior is unchanged.
- Global/host middleware now observe mux 404/405 errors after the early render,
  where they previously saw nil. This is intentional; consumption or translation
  uses `CatchErrors`, while the response contract stays the same.
- Host middleware runs before the host mux, including `Isolate` host 404/405
  responses. Requests served by the primary table through `FallbackToPrimary`
  bypass host middleware. B7-007 is a documented ordering clarification, not a
  behavior change beyond the early-error boundary.

## B7-006 — upgrade JSON reports only executed work

- Structured `andurel upgrade` (`--json`/`--agent`) remains non-interactive and
  never runs `go mod tidy` or `andurel tool sync`. The fabricated
  `commands_run` entries were removed.
- `commands_run` now contains only subprocesses the invocation actually
  attempted, in execution order, including read-only safety checks such as
  `git status --porcelain`. Failed attempts carry a `(failed)` suffix.
- Required tidy and tool-sync work is returned as conditional warnings and
  breadcrumbs. A dry run phrases mutation/install/tidy follow-ups as proposed
  work that was not run; a pending repair says the file and tool changes are
  proposals until `andurel upgrade --repair` runs.
- Structured errors preserve the failed report under `upgrade` and the actual
  attempted commands under `commands_run`; they never emit a success envelope.
- `ok: true` means the upgrade mutation succeeded. It does not certify that the
  project builds, that `go mod tidy` ran or that changed tool binaries are
  installed. Human mode keeps its prior tool-sync and advisory-tidy behavior.
- B7-003 stage semantics are documented: a content stage may be
  `status: "skipped"`, `ok: false`, `not_applicable: true` while the
  command-level envelope remains `ok: true`. Consumers must inspect the stage
  status; the schema is unchanged.

## B7-039 — synthetic test mains are identified by provenance

- The payload-import false positive came from treating a generated test main as
  project source because it lived under an in-root `GOCACHE`. The old
  "outside project root" requirement is gone.
- The filter now uses a conservative composite: go/packages identity
  (`main`, `.test` package path, exactly one Go file), the actual Go build-cache
  data-artifact layout (`<cache>/<2 hex>/<64 hex>-d` matching the action ID
  prefix), and the exact `// Code generated by 'go test'. DO NOT EDIT.` header.
- `GOCACHE` is resolved lazily only when a test-main candidate exists. Empty,
  `off`, failed or unavailable lookups do not filter source. Symlink targets
  are resolved before containment is accepted.
- Genuine same-package and external `_test.go` violations, ordinary generated
  project files, and a real `.test` main package with a generated-looking header
  remain violations in every cache layout. There is no blanket `.test`,
  generated-header or cache-directory ignore.
- A pinned Go/x/tools metadata test makes a future generated-main or cache
  layout change a visible failure instead of silently weakening the filter.

## Existing applications

- Route middleware and route consumers need no change.
- Global or host middleware that consumes, translates or retries errors must
  add `CatchErrors` around its layer. Without it, errors render earlier than in
  beta.7.
- Update anduin and inertia together. Running new anduin with an old inertia
  capture produces a plain 500 fallback for early host/global errors rather
  than a themed page.
- After an upgrade changes `go.mod` pins, run `go mod tidy`; after tool
  versions change, run `andurel tool sync`. Structured upgrade output now
  reports these as follow-ups rather than claiming they ran.
- If `andurel tool set-version narsilc` reports a runtime mismatch, run the
  printed `go get github.com/mbvlabs/narsilc@<version>` and `go mod tidy`.
  `andurel doctor` reports the same mismatch.
- No database migration or application source rewrite is required by these
  fixes.

## Known limitations and intentional observations

- A middleware context that is created and never passed to `next` cannot be
  recovered through the existing API.
- Delayed route/`CatchErrors` renders preserve values, not resources already
  released by middleware that returned.
- If bytes were already delivered, a later error cannot replace them; the
  router logs the discard and avoids a second render.
- Inertia header rollback is a narrow metadata policy, not a general response
  header transaction. Arbitrary success headers remain discarded.
- Kiks persists the bag exactly once, on the first response write:
  `persistWriter` saves in `WriteHeader`, `Write` or `Flush`/`FlushError`
  before forwarding that operation, using the status observed at that write.
  If the response never writes, the `next` return path saves once at status
  200. `AddFlash` after the response starts is not persisted because the only
  save already occurred at the first write; add flashes before writing. A
  `CatchErrors` scope that needs the kiks bag must be inside `Jar.Middleware`;
  an outer scope renders after kiks has already saved (status 200 when nothing
  wrote first).
- The old-capture safety fallback is one plain 500, not themed error support.
- `GOCACHE=off` is rejected by Go before package loading; a failed `go env`
  lookup conservatively keeps source analysis rather than hiding code.
- B7-040 remains an observation without a confirmed standalone reproduction and
  is not a release blocker on current evidence.
