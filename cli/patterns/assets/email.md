# Email

Email is authored as React Email components in TSX under `emails/` and exported
by `andurel sync emails` to committed Go `text/template` files under
`emails/templates/`. Go owns the data: a struct in `emails/` declares
`ToHTML`/`ToText` and calls `renderHTML`/`renderText`. Because the templates are
committed, `go build`, tests and sending never need Node.

`emails/` is one directory for both languages: Go ignores `.tsx`/`.ts` files and
the `_`-prefixed `_components/` and `_generated/` directories, so the Go package
and the React Email sources coexist. The Go package is named `emails`; import it
as `<module>/emails`.

An agent edits three things per email: the TSX component in `emails/`, the Go
struct in `emails/`, and one fixture in `emails/previews.go`.

## Files

| Path | Role |
| --- | --- |
| `emails/theme.ts` | light and dark hex palettes; hand-edited |
| `emails/_components/layout.tsx` | shared `Layout`: `<Html>`/`<Head>`, color-scheme metas, dark-mode style block, card and footer |
| `emails/_components/code-box.tsx` | shared verification-code box |
| `emails/<kebab>.tsx` | one component per email; agent-authored |
| `emails/_export.tsx` | export script: renders each component to `.html`/`.txt` templates |
| `emails/_generated/props.ts` | generated `XProps`, `XHtmlVars`, `XTextVars`; do not edit |
| `emails/_generated/manifest.ts` | generated component manifest; do not edit |
| `emails/tsconfig.json` | typecheck config for `emails/` |
| `emails/<snake>.go` | Go struct plus `ToHTML`/`ToText`; agent-authored |
| `emails/render.go` | embeds `emails/templates/*` and executes them with `text/template` |
| `emails/previews.go` | fixture entries used by `andurel email render` |
| `emails/templates/<snake>.{html,txt}.tmpl` | generated by `email:export`, committed; do not edit |
| `cmd/emails/main.go` | preview renderer run by the CLI; a dev tool, never deployed |
| `services/<name>.go` | send helper that composes the message and enqueues it |

Naming is derived: `VerifyEmail` in `emails/verify_email.go` renders
`emails/templates/verify_email.*.tmpl` and is authored as
`emails/verify-email.tsx`. Snake_case and kebab-case are generated from the Go
type name.

### emails/welcome_email.go
```go
package emails

import pkgemail "github.com/mbvlabs/andurel/pkg/email"

type WelcomeEmail struct {
	UserName string
}

var _ pkgemail.Transformer = (*WelcomeEmail)(nil)

func (w WelcomeEmail) ToHTML() (string, error) {
	return renderHTML("welcome_email", w)
}

func (w WelcomeEmail) ToText() (string, error) {
	return renderText("welcome_email", w)
}
```

### services/<name>.go
```go
package services

import (
	"context"

	"app/domains"
	appemails "app/emails"
	"app/queue/jobs"

	"github.com/mbvlabs/andurel/pkg/email"
	"github.com/mbvlabs/andurel/pkg/storage"
)

// Pass i.queue.InTx(tx) from inside storage.AtomicOps so the email is only
// delivered if the user commits.
func (i Identity) sendWelcome(ctx context.Context, queue storage.InsertQueue, user domains.User) error {
	message := appemails.WelcomeEmail{UserName: user.Email}

	data, err := email.Compose(
		message,
		user.Email,
		i.defaultSenderSignature,
		"Welcome",
	)
	if err != nil {
		return err
	}

	_, err = queue.Insert(ctx, storage.SendTransactionalEmailArgs{Data: data}, nil)
	return err
}
```

## Components

Shared components (import from `./_components/...`):

| Component | Props | Use |
| --- | --- | --- |
| `Layout` | `title`, `preview`, `children` | shell for every email: `<Html>`/`<Head>`, color-scheme metas, dark-mode style block, 600px card, footer |
| `CodeBox` | `label`, `code` | verification-code block |

`react-email` primitives commonly used (import from `react-email`):
`Html`, `Head`, `Preview`, `Body`, `Container`, `Section`, `Text`, `Heading`,
`Button`, `Hr`, `Img`, `Link`, `Row`, `Column`. Use `Section` for a padded
block, `Heading as="h1"` for the title, `Button` for a call to action, and
`Preview` for inbox preview text. Set styles with `style={{ ... }}` objects
that reference `theme` tokens.

`Layout` also defines the class hooks used by its `<style>` block: the
dark-mode hooks (`email-bg`, `email-card`, `email-fg`, `email-muted`,
`email-muted-bg`, `email-border`) and `email-px` for the mobile gutter. Keep
them on the elements they style; light hex values stay inline as the baseline,
and the `prefers-color-scheme` block is a progressive enhancement for Apple
Mail and Outlook.com.

## Rules

- Author email markup only in `emails/`. `emails/templates/*` and `emails/_generated/*` are generated: never edit them by hand. Change the Go struct or the TSX, then run `andurel sync emails`.
- An email is a Go struct in `emails/` with exported fields and `ToHTML`/`ToText` that call `renderHTML`/`renderText` with the snake_case template name; implement `pkgemail.Transformer` so `email.Compose` can render both bodies.
- Scalar fields only: `string`, the integer kinds and `float64`. Slices, maps, bools, structs, pointers and interfaces fail `andurel sync emails` with "format it into a string field in Go". Pre-format lists and optional text into strings in the service.
- Render every field in both the HTML and the text output. The export fails if a prop has no placeholder or if the output has a `{{` that is not a generated placeholder.
- Never write a literal `{{` (or a stray `}}`) in TSX or CSS. Exported output is a Go `text/template`; placeholders come only from the generated `XHtmlVars`/`XTextVars`.
- Hex colors only, from `theme.ts`. Never use `oklch()`, `var()`, or `rgb(0 0 0)` space syntax: Gmail can strip every style on an element that uses them.
- Physical spacing only: `padding`, `padding-top`, `padding-right`, `padding-bottom`, `padding-left`, `margin` and the physical margin longhands. Never use `padding-inline`, `padding-block`, `margin-inline`, `margin-block`, `inset`, or `border-inline-*`; Gmail, Outlook and Yahoo drop them.
- No Tailwind and no `<Tailwind>`: style objects with `theme.ts` tokens only. Tailwind v4 emits logical properties and oklch, which is why the old compiler was removed.
- Add a `Preview` entry in `emails/previews.go` for every email. It is the only data `andurel email render` uses, and a missing entry hides the email from the gallery.
- Send transactional mail by enqueuing `storage.SendTransactionalEmailArgs` on a `storage.InsertQueue` from a service, not directly from a handler. When the email depends on data written in the same use case, pass `i.queue.InTx(tx)` from inside `storage.AtomicOps`.
- Job args persist in `river_job`. An email that carries a secret (verification code, reset link) is not rendered at enqueue time: enqueue a job with the user id and let its worker mint the secret and render the email, as `jobs.SendVerificationEmailArgs` and `jobs.SendPasswordResetEmailArgs` do.
- `andurel build` and `andurel run` run `andurel sync emails` and the export automatically before compiling or rebuilding. Run `andurel sync emails` yourself after editing `emails/*.go` or `emails/**`; `andurel doctor` reports stale generated output in the "emails export" check.
- `cmd/emails` is a development tool. `andurel build` excludes it; never deploy it.

## The loop

1. Edit `emails/<name>.tsx`. Run `andurel email render --watch --open` to
   render once, open `tmp/emails/index.html`, and keep the gallery live while
   you edit. The gallery has desktop (600px), mobile (375px), dark (600px) and
   text panes, and reloads itself when the render changes.
2. `--watch` also runs the same steps as `andurel sync emails` whenever
   `emails/**` changes: it scans exported structs in `emails/*.go` that have
   `ToHTML`, writes `emails/_generated/props.ts` and `manifest.ts`, then runs
   the project's `email:export` script to write `emails/templates/*`. Errors
   print in the terminal and the watcher keeps running.
3. For a one-shot run, use `andurel email render --json`. It runs the real Go
   `ToHTML`/`ToText` path with the fixtures from `emails/previews.go` and writes
   `tmp/emails/<name>.html`, `tmp/emails/<name>.txt` and `tmp/emails/index.html`.
   Read the `.html` and `.txt` files it reports. Agents should use this form.
4. Run `andurel sync emails` yourself when you need `--skip-export` or a
   machine-readable report, and `andurel email render verify_email` to render
   one email.
5. Run `andurel doctor`, then commit `emails/`, including the generated
   `emails/_generated/*.ts` and `emails/templates/*.tmpl` files.

The gallery is the truth loop: it renders the committed Go templates with the
Go `ToHTML`/`ToText` path, including the Go substitutions, so always check it
before sending.

## Providers

`EMAIL_PROVIDER` selects the mail transport. `mailpit` (the default) captures
mail locally and the app refuses to start in production with it. Set
`EMAIL_PROVIDER=smtp` for a production relay and configure `SMTP_HOST`,
`SMTP_PORT` (default `587`), `SMTP_USERNAME`, `SMTP_PASSWORD`, and `SMTP_TLS`
(`starttls`, `tls` for implicit TLS on port 465, or `none` for a local relay).
