# Route

A route is data: a declared path, name, and parameters. `pkg/routing` provides
the route model; the `Router` type lives in `pkg/anduin`. Route data stays in
the application under `routes/`. Inertia projects map route data to TypeScript
helpers with `andurel sync routes`.

## Files

### routes/<resource>.go
```go
package routes

import "github.com/mbvlabs/andurel/pkg/routing"

const UserPrefix = "/users"

var (
	UserIndex  = routing.NewSimpleRoute("", "users.index", UserPrefix, routing.TypeScriptRoute())
	UserShow   = routing.NewRouteWithStringID(":id", "users.show", UserPrefix, routing.TypeScriptRoute())
	UserCreate = routing.NewSimpleRoute("", "users.create", UserPrefix, routing.TypeScriptRoute())
)
```

### resources/js/routes.ts
```ts
// Code generated by andurel; DO NOT EDIT.
//
// Helpers are generated for routes marked routing.TypeScriptRoute()
// (routing.InertiaRoute() is a deprecated alias).
//
// Call helpers while rendering: routes.widgetShow(id), not
// const url = routes.widgetShow(id). configureRouteHosts runs after the app
// boots, so a module-scope constant keeps an empty origin (or a stale value
// under SSR) and will not pick up the configured host.

type HostOrigins = Record<string, string>

let origins: HostOrigins = {}

/** Call once at boot with Inertia shared hosts prop. */
export function configureRouteHosts(next: HostOrigins) {
  origins = next
}

function origin(host: string): string {
  return origins[host] ?? origins.primary ?? ''
}

export const routes = {
  userCreate: routeHelper({
    host: 'primary',
    path: () => '/users',
  }),
  userIndex: routeHelper({
    host: 'primary',
    path: () => '/users',
  }),
  userShow: routeHelper({
    host: 'primary',
    path: (id: string) => `/users/${id}`,
  }),
}

function routeHelper<Args extends unknown[]>(def: {
  host: string
  path: (...args: Args) => string
}) {
  const full = (...args: Args) => origin(def.host) + def.path(...args)
  return Object.assign(full, {
    path: def.path,
    host: def.host,
  })
}
```

## Rules

- Declare route data in `routes/`; never define the `Router` type there.
- Route variables are the single source of truth for URLs used by handlers.
- Bind a route to a named virtual host with `routing.Host(...)` when needed.
  Build the host registry with `routing.NewHosts(...)`, pass it to
  `anduin.NewRouter(anduin.WithHosts(hosts), ...)`, and pass the same value to
  `FullURL(hosts, ...)`.
- Mark every route the frontend links to with `routing.TypeScriptRoute()`
  (`routing.InertiaRoute()` is a deprecated alias).
  `andurel sync routes` skips routes without it, so JSON/asset/health routes
  never appear in `routes.ts`.
- The TypeScript key is the **route variable name in lower camelCase**, not the
  route's declared `name`: `UserIndex` → `routes.userIndex`, and
  `PasswordEdit` → `routes.passwordEdit`. Helpers are flat and sorted
  alphabetically in the generated object; two variables that lower-case to the
  same key make the generator fail. The declared name (`users.index`) is for
  inspection and telemetry only.
- Run `andurel sync routes` after changing Inertia route data.
- `routes/` is data: the manifest can be inspected without a running server.
- Call a helper as `routes.userShow(id)` for an absolute URL (host resolution
  happens after `configureRouteHosts` has run at boot) and as
  `routes.userShow.path(id)` when the router needs a relative path, such as
  `<Link href>`. Build helpers at render time, not in a module-scope constant
  that runs before the shared `hosts` prop is configured.

## Checklist

- [ ] Path, name, and params declared with the `routing` helpers.
- [ ] `routing.TypeScriptRoute()` set on every route the frontend links to.
- [ ] Handler `Register` uses `routes.<Name>.Path()`.
- [ ] `andurel sync routes` run for Inertia projects; the generated key is the
      lower-camelCase variable name.
- [ ] `andurel inspect routes --json` reports the new route.
