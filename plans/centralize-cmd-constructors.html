One composition package for shared cmd wiring

Brief

cmd/app and cmd/queue both copy newEmailSenders, newTelemetry, and newDatabase. Explore a way to write those constructors once without putting Fx modules back into pkg/*. Review decision: internal/runtime is the composition package — it assembles the full process graphs. Generated internal/ is application space, not framework-owned.

01

What is duplicated today

Each generated Fx binary is its own composition root. The constructors that map config.* onto pkg/telemetry, pkg/email, and pkg/storage are copy-pasted into both cmd/app/main.go and cmd/queue/main.go. Seeds and SSR do not use this graph.

Constructor cmd/app cmd/queue cmd/seeds cmd/ssr
newTelemetry yes yes — —
newEmailSenders yes yes — —
newDatabase yes yes inline, no OTel —
newQueueInsert app only — — —
newQueueProcessor — queue only — —
newInertia Inertia apps — — own runtime

This is intentional V2 layering: packages accept values, generated config/ loads env, and Fx wiring lives in the app. The miss is that the wiring has two copies.

02

Recommendation

Add a generated, application-owned internal/runtime package. Generated internal/ is application space (layer-placement already puts reusable plumbing there). It is the composition root: every Fx provider and invoke for a process is assembled here. models.Module, services.Module, and the rest still declare their constructors in their own packages (generators keep injecting there). internal/runtime is the only place that lists them into a process graph. Each cmd/* loads env, builds a signal context, and calls fx.New(runtime.App(ctx)) or fx.New(runtime.Queue(ctx)).

internal/runtime assembles every process graph; package Module vars still live next to their types
03

Why not the other homes

internal/runtime — decided

Go package name runtime, path internal/runtime. Generated internal/ is application space. Assembles every Fx provider and invoke for App and Queue. Adding SES or Postmark in NewEmailSenders is a user edit and must not be upgrade-owned.

decided full graphs app-owned internal/

pkg/* Fx modules — reject

v2.0.0 removed telemetry.Module from the package and put constructors in main on purpose. Packages must not read env or depend on generated config. Putting Fx back into pkg reverses that.

reject breaks v2 invariant

Top-level runtime/ — reject

A root runtime/ package is importable outside the module and sits beside domain packages. Layer-placement already reserves internal/ for reusable plumbing. Keep composition unexported from other modules.

reject use internal/runtime

config/ — reject

Config loads and validates env. Constructing Postgres, OTLP exporters, and Mailpit clients is a different layer. Keep config.Module as constructors of structs only.

reject layer mix
04

Shape of internal/runtime

Every Fx provider and invoke for a process lives in internal/runtime. Package-level Module vars stay in config/, models/, services/, and so on so generators keep injecting there. runtime.App and runtime.Queue are the only graphs.

internal/runtime/app.go 
func App(ctx context.Context) fx.Option {
  return fx.Options(
    fx.Provide(func() context.Context { return ctx }),
    config.Module,
    Shared,          // telemetry, email, database
    QueueInsert,
    Inertia,         // Inertia scaffolds only
    models.Module,
    services.Module,
    controllers.Module,
    cookies.Module,
    router.Module,
    fx.Invoke(startServer),
  )
}
internal/runtime/queue.go 
func Queue(ctx context.Context) fx.Option {
  return fx.Options(
    fx.Provide(func() context.Context { return ctx }),
    config.Module,
    Shared,
    queue.Module,
    QueueProcessor,  // constructor + lifecycle invoke
  )
}
cmd/app/main.go — after 
app := fx.New(runtime.App(ctx))
cmd/queue/main.go — after 
app := fx.New(runtime.Queue(ctx))

Move into internal/runtime:

  • Full App and Queue option graphs
  • NewTelemetry, NewEmailSenders, NewDatabase
  • NewQueueInsert, NewQueueProcessor, processor lifecycle
  • NewInertia on Inertia scaffolds
  • startServer, startInBackground, stopAndWait (tests move to internal/runtime)
  • Blueprint.Main.ServiceProvides range — inject into Shared so both processes see them

Leave in the binary:

  • config.LoadEnvironment, signal context, fx.New, start/stop, os.Exit

07

Decided

Package: internal/runtime

Go package name runtime. Path is internal/runtime, not a top-level runtime/. Generated internal/ is application space; do not framework-own these files.

All Fx providers go in internal/runtime

runtime.App and runtime.Queue assemble the full graphs, including package Modules, infrastructure constructors, Inertia, QueueInsert, QueueProcessor, and startServer / processor lifecycle. cmd binaries only load env and call fx.New. Generators still inject into models.Module / controllers.Module / queue workers.

QueueProcessor lives in runtime

Opt-in module used only by runtime.Queue, matching QueueInsert on the app graph.

No upgrade note

Still alpha. Scaffold and goldens only. Existing duplicated constructors are not migrated and are not documented as a manual action.
