## Independent review findings — design hold

Review blocked the post-unwind design on three issues. No implementation change
was made after the review; the characterizations below are opt-in red tests in
`pkg/anduin/router_error_context_test.go` and fail against the retained
implementation.

1. **P1 — retained context is already canceled / resources released.** The
   boundary stores the live child context and drains it after the global chain
   unwinds. A middleware using `ctx, cancel := context.WithCancel(ctx); defer
   cancel()` (or a transaction middleware that rolls back in `defer`) leaves the
   ErrorHandler with `ctx.Err() == context.Canceled` and released resources.
   Test: `TestDesignHoldCanceledContextAndReleasedResource`.
2. **P2 — kiks saves before the host/global render, so bag mutations do not
   persist.** The current cookie test only proved a direct `Set-Cookie` from
   the ErrorHandler. A kiks-like bag middleware saves on its `next` return
   (status defaults to 200) before the host/global drain, so a flash added by
   the ErrorHandler and a 409 error page cannot produce a flash cookie; the
   status-based flash decision is wrong. Test:
   `TestDesignHoldBagMutationNotSavedAfterUnwind`.
3. **P2 — repeated `next` calls keep the first context.** `recordError` sets
   `errCtx` only once but replaces `err` each time. If a middleware calls
   `next(ctxA)` then `next(ctxB)` and both fail, the ErrorHandler receives
   `ctxA` with `errB`. Test: `TestDesignHoldRepeatedNextKeepsFirstContext`.

## Prototype finding / design decision

This section records the retained pre-review design. The independent-review
hold above supersedes its acceptance; it is not a claim that the design is
cleared.

Rendering directly inside every wrapped `next` before upstream unwinds conflicts
with response-capturing middleware. `pkg/inertia`'s middleware replaces the
writer with an unexported `captureWriter` and, on a non-nil error, returns
without committing the capture:

```go
err = next(ctx)
ctx = anduin.ReplaceResponseWriter(ctx, original)
if err != nil {
    return err
}
...
return captured.commit()
```

A render performed inside that boundary is therefore discarded. Consuming the
error (returning nil) would let inertia commit, but breaks middleware that
relies on a returned error for rollback or observation, which the spec forbids.
A cross-module inertia change is out of T02's published-package scope.

Implemented design (contract-preserving):

- `applyMiddleware` wraps every middleware layer with `Router.errorBoundary`.
  The boundary records the context the layer was called with (the deepest
  context actually passed to the failing layer) and the latest error. It never
  consumes an error, so `errors.Is`/`errors.As`, wrapping and rollback continue
  to see the original error.
- A layer returning nil has consumed the error below it; the boundary clears
  the record so the middleware's response stays in charge.
- Route/handler errors are drained once by `routeHandler` after route middleware
  unwinds and before the mux returns. This is the existing consumption point, so
  host/global middleware still observe nil for route errors exactly as before,
  and inertia's capture commits normally.
- Host/global middleware errors are drained once by `serve` after the global
  chain unwinds, with the recorded deepest context. This is the existing render
  point, so response-writer restoration, kiks cookie persistence and returned
  error observation are unchanged.
- The `ErrorHandler` always receives the latest (outermost) error but the
  deepest observable context. Contexts a middleware created but never passed to
  `next` remain unrecoverable, as the spec allows.

Deviation to report: the literal "render at each boundary before upstream
resource middleware unwinds" is met for route/handler errors but not for
host/global errors, which drain at `serve` because inertia discards an
uncommitted capture on the error path. Rendering earlier for host/global would
require either a cross-module inertia change or consuming errors (breaking
observation). Local evidence below shows the accepted observable contracts are
preserved; if literal early rendering for host/global is a hard gate, this is a
design escalation rather than a safe source change.

## Remaining integration risks

**Blocking design hold.** The independent review's P1 (canceled/released
retained context), P2 (kiks save before host/global render, bag/flash mutation
lost) and P2 (repeated `next` keeps the first context while keeping the latest
error) are reproduced by the opt-in tests. The implementation was not changed
after the review; oracle scope is pending. A likely fix requires rendering or
snapshotting before upstream unwind, preserving kiks save ordering/status, and
tracking the context of the latest failing pass rather than the first. Those are
design changes, not test-only edits.

1. **Published dependency proof is T09.** Local `GOWORK=off` uses the routing
   v0.9.0 already in the module cache. The real proof needs a published anduin
   version consumed by kiks/inertia under `GOWORK=off` with proxy/checksum
   verification. No version was guessed, tagged or published here.
2. **Host/global render timing is unchanged from beta.7.** Kiks saves cookies
   before the host/global error page is rendered, so a session cookie persists
   but flash status classification is still based on the pre-error status. Route
   errors render before the persist middleware unwinds. Do not claim a flash
   improvement without a follow-up.
3. **Contexts never passed to `next` are not recoverable.** This is the spec's
   explicit API limit and is covered by the implementation comment.
4. **Response-capturing route middleware.** A route middleware that captures and
   discards its buffer on error can still lose the route error page; this is the
   pre-existing behavior at the route consumption point, not a new one. Inertia's
   global capture is handled by draining route errors inside it and saving
   nil-return behavior for host/global errors.
5. **No commits/tags/push/pins.** The release version, CHANGELOG cut and pin
   update remain owner/orchestrator work.
