## Implementation

- `cli/narsilc_runtime.go` parses `go.mod` with `golang.org/x/mod/modfile` and
  compares the required `github.com/mbvlabs/narsilc` module version with the
  requested tool version using `golang.org/x/mod/semver`. It does not mutate
  module files.
- Runtime states are explicit: `aligned`, `mismatch`, `missing`, `replaced`
  and `unverifiable`. Local and versioned `replace` directives are reported as
  replaced/unverifiable, never aligned. Unreadable or malformed module data is
  unverifiable. A missing requirement is not injected.
- `andurel tool set-version narsilc <version>` now inspects `go.mod` only after
  the tool/lock/binary update succeeds. On mismatch it prints the exact
  `go get github.com/mbvlabs/narsilc@<version>` and `go mod tidy` steps. Install
  failures return the original error and do not emit runtime guidance.
- The same result is available through the structured `--json`/`--agent`/`--md`
  surface. `data.narsilc_runtime` carries the state, `warnings` and
  `next_steps`; remediation is also exposed as breadcrumbs. Human progress is
  suppressed so structured stdout remains a valid envelope.
- `andurel doctor` has a new `narsilc runtime` configuration check in both
  human and structured surfaces. A mismatch is a warning with details and the
  same actionable hint/commands; replacements and unreadable module data warn
  as unverifiable; an absent runtime requirement is reported as not required,
  not as aligned.
- Unrelated tools keep their existing install/human behavior; the structured
  set-version envelope is available uniformly because the command now supports
  `--json`/`--agent`/`--md`.
