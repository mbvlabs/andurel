Implementation plan · Andurel · rev 2

Rework testing around reliable golden files

Brief

Tests pass locally but fail on CI too often. Start from scratch: remove the current suite, rebuild around golden-file generation and sync tests that write deterministic, byte-stable outputs so local and CI always agree.

Rev 2 from review: drive every golden through a built andurel CLI binary (not in-process generator APIs). Fix product output so tests do not need formatting/normalization layers — assert file bytes as written.

01

Core approach

Goldens are integration tests of the product CLI. Build one binary once, run real andurel generate … / andurel sync … against fixture projects, compare written files to committed goldens.

Drop What we stop doing

  • Calling generator packages directly from tests
  • Post-hoc scrubbers (secrets, versions, paths, lock timestamps)
  • Test-only formatting / rewriting of output before assert
  • Overlapping e2e tree snapshots + generator package goldens
  • Unpinned go install of formatters that change bytes

Do What replaces it

  • Build andurel once in TestMain
  • Copy a fixture project into a temp dir
  • Exec the CLI with the same flags users run
  • Read the files the CLI wrote; goldie-assert them as-is
  • Make the CLI emit stable bytes (seeded secrets, pinned tools, stable module path in fixtures)
02

How — step by step

The harness stays thin on purpose. Determinism lives in the product and in fixtures, not in test helpers.

  1. Product: make output byte-stable

    Before new goldens land, remove the reasons tests currently scrub. Scaffold secrets come from a fixed seed or a test-only env (ANDUREL_TEST_SEED / injected RNG) when set — never random on CI. Version banners in generated headers use the same version the binary reports. Lock appliedAt is either omitted in test mode or written as a fixed epoch. FormatGoFile always invokes pinned tool versions from layout/versions (same pins local and CI install), never whatever happens to be on PATH.

  2. Fixtures: freeze the project shape

    Each scenario is a directory under testdata/fixtures/<name>/: a minimal Andurel project (go.mod with a fixed module path like example.com/app, migrations, stubs for controllers/router as needed). Copy into t.TempDir(). No rewriting of module paths at assert time — the fixture already uses the stable name.

  3. Harness: build CLI, run command, assert files

    TestMain builds andurel into a shared temp bin once (same pattern as today’s e2e, but without a normalizer). Each test: copy fixture → exec.Command(bin, args...).Dir(project) → on success, for each path in the scenario’s capture list, read bytes and goldie.Assert. On failure, dump CLI stdout/stderr. Update mode: -update / GOLDEN_UPDATE=1 via goldie. That is the entire assert path — no format, no regex replace, no JSON rewrite.

  4. Scenario tables for generate + sync

    One table-driven test file (or two: generate / sync). Each row: fixture name, argv, list of relative paths to capture. Example: fixture widgets_crud, args generate scaffold Widget, capture models/widget.go, controllers/widgets.go, views, routes, factory. Sync row: fixture with an existing factory that has custom helpers, args sync factory Widget --sync, capture the factory file.

  5. CI = local

    One just recipe installs pinned tools and runs the golden package. CI runs that same recipe, then fails if goldens are dirty when run with update, or simply runs tests and fails on mismatch. No second e2e golden job. Go version pinned without check-latest.

illustrative harness · no normalizer 
func TestGenerateGoldens(t *testing.T) {
  for _, sc := range generateScenarios {
    t.Run(sc.Name, func(t *testing.T) {
      project := copyFixture(t, sc.Fixture)
      runCLI(t, andurelBin, project, sc.Args...)  // fail on nonzero exit
      for _, path := range sc.Capture {
        got := readFile(t, project, path)
        g.Assert(t, filepath.Join(sc.Name, path), got)  // raw bytes
      }
    })
  }
}

03

Why local ≠ CI today

  • Unpinned formatters — most workflows install templ / golines / goimports without versions; release-readiness pins them. Bytes drift.
  • PATH-dependent FormatGoFile — product shells out to whatever is installed; tests then try to compensate.
  • Random scaffold secrets + lock timestamps — e2e normalizer papers over instability instead of fixing the writer.
  • Two golden stacks — generator package APIs vs full e2e CLI, different harnesses, same intent.

The rework attacks the root: stable writers + CLI-only goldens. If a golden is flaky, the product is wrong — not the test helper.

Third wave — needs pinned external tools proven first.

Later full-tree golden with seeded secrets; replaces today’s e2e scaffold snapshot.

Thin unit tests

Only after goldens: parsers, flag errors, pkg modules — no output formatting.

05

Milestones

Phase 0 · Clean slate

Delete old tests and goldens; slim CI

Remove *_test.go (scope per open question on pkg/*), e2e suite, and golden trees. Keep contract scripts. CI runs vet + contracts only until Phase 2 lands.

Phase 1 · Product stability + thin harness

Fix writers; add CLI TestMain harness

Pin tool versions in one module; make scaffold/lock/header output deterministic under test seed; point FormatGoFile at pinned binaries. Add internal/goldentest: build binary, copy fixture, run CLI, assert raw files. Prove with one trivial generate that already writes stable output.

Phase 2 · Generation goldens

Table-driven andurel generate … scenarios

Port today’s high-value model / controller / scaffold cases as CLI argv + capture lists. Prefer fewer scenarios that stay green over a large flaky set.

Phase 3 · Sync goldens

Factory sync via CLI, then routes/payloads

Fixtures include hand-edited factory helpers; run sync factory / sync factories; assert files. Add check-mode JSON goldens only if stdout is already stable (no test reformatting).

Phase 4 · Thin extras

Units and andurel new tree golden

Reintroduce non-file unit tests sparingly. One or two andurel new matrix goldens replace the old e2e snapshot suite — still CLI-driven, still raw bytes.

07

Risks

Risk Severity Mitigation
Coverage hole between delete and first goldens High Do not merge Phase 0 alone to master; ship Phase 1–2 on the same branch series.
Product changes for determinism touch user-visible output Med Prefer test-seed env over changing default production randomness; document any lock/header changes.
Building CLI in TestMain needs network/modules Med Same as current e2e; cache modules in CI; fail loud if build fails.
Temptation to add a “small” normalizer later Low Hard rule: if bytes differ, fix the CLI or the fixture — never add scrubbers.
