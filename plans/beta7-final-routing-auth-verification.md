## New routing finding: host middleware context is lost

**Fixed and retested.** The original defect caused host middleware context values to be lost, breaking host-wide authentication. `serve` bound the request to the global context before running host middleware, then `dispatch` passed that stale request to ServeMux. Dispatch now binds the latest context to the latest request after host middleware, preserving request replacements. `pkg/anduin/router_host_context_test.go` covers context ordering, request replacements, fallback isolation, path values and mounted handlers. The original generated-app test and HTTP repro now pass as recorded above; the full Anduin suite, `go vet ./...`, `go fix ./...` and gofmt also pass.

## New security finding: in-flight old-password login survives password reset

**FAIL, generated auth security defect.** Repro is the two coordinated HTTP trials in the table. Immediately after each script, take the session cookie (without printing it) from `race-login.headers` and request `/some/protected` with it on the same server: 200. The scratch barrier only delays execution; no authentication or persistence behavior is altered. It proves that an old password accepted immediately before reset can obtain a valid post-reset session. `services/authentication.go` first verifies the old hash, `domains/user.go` `RehashPassword` detects the changed hash and returns the freshly locked user including the **new** `SessionVersion`, then `handlers/auth.go` stores that version in an authenticated cookie. `middleware.AuthOnly` therefore accepts the cookie even though the reset was supposed to revoke sessions. This is distinct from the fixed hash overwrite; likely fix requires rejecting/retrying authentication when the verified hash or session version has changed, rather than treating the newly returned row as authenticated. Do not log cookie values or reset tokens in any follow-up.

**2026-11-02 auth follow-up: PASS with local-source scaffold; historical failure above retained.** Login now calls `RehashVerifiedPassword`, which checks the verified hash and session version against the locked row. A mismatch returns generic invalid credentials; a successful rehash keeps the verified session version. A later reset still invalidates any already-issued cookie by bumping that version. The original `RehashPassword` preservation behavior remains unchanged.
