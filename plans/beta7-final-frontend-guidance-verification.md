## Verdict

**Fail: generated app tests fail after a frontend build, and supplied 4xx messages are still dropped.** These are not setup issues. The release candidate is not accepted on this scope. Subsequent checks are recorded below, with their precise limits.

New reproduction: build CLI from this integration tree, `andurel new auditreact`, apply local replacements for `anduin`, `inertia`, `routing`, and `storage`, install dependencies, build the frontend with `pnpm build`, configure a Postgres database, start `andurel run`, and run `andurel verify --with-tests --json`. The generated stage passes but `TestHomePageIsPublic` reports `inertia status = 409, want 200`, and `TestMethodNotAllowedRendersNotFoundPage` reports `inertia status = 409, want 405`. Generated `app/runtime_test.go:477-487` sends `routes.ViteBuild.FullURL(hosts)` as `X-Inertia-Version`, whereas the renderer now uses the manifest-derived version. Fix the generated test helper to obtain the actual renderer version (without weakening mismatch coverage), then repeat the complete acceptance. The JSON report had 45 passing tests, 2 failures, 0 skipped tests; content stage was not applicable. It also printed a warning about an older unowned test container, which was not touched.

**F12b remains a reproducible failure.** In the scratch generated app add routes returning `anduin.BadRequest(errors.New("bad <script>alert(1)</script>"))` and `anduin.NotFound(errors.New("missing <script>alert(1)</script>"))`. With `X-Inertia: true` and the current version, GETs return the correctly themed 400/404 components but no `message` property. An `anduin.Forbidden(errors.New(...))` returns plain `Forbidden`, also losing the cause. `anduin.Errorf(400/404, ...)` does put the message in themed Inertia props. However, even those explicit-message routes requested with `Accept: application/json` respond `{"error":"Bad Request"}` / `{"error":"Not Found"}`, omitting the supplied message. This contradicts the beta.6 requirement to retain messages in the default error response and the beta.7 release-note blanket claim. Exact probe routes are in scratch `app/runtime.go`; no framework implementation was edited.

**Security clarification after this audit:** `BadRequest(err)`, `NotFound(err)` and `Forbidden(err)` store `err` as an underlying cause, not a public message. `anduin.Message` explicitly selects `HTTPError.Message` or the status text, never the cause; `HTTPError.Error()` can contain private causes and must not be used as the response. Thus the cause-only examples above should remain generic. Use `anduin.Errorf` or an explicit `HTTPError.Message` for text intended for clients. The JSON loss of those explicit 4xx messages was a real gap; the shared Inertia JSON handler now retains them, while suppressing 5xx messages even when a wrapped sentinel maps to a 4xx. The original verdict describes the prior audit and is not a new full acceptance run.

**F12b follow-up, 2026-11-02: PASS for the explicit-message fix, limited scope.** A freshly generated React scaffold at `/home/mbv/work/beta7-f12b-scratch/f12bapp` used local integration-module replacements. A probe started the real anduin router and generated `handlers.MapError` on an HTTP test server (not the full app process or browser). JSON responses were 400 `{"error":"bad \u003cinput\u003e"}` for a wrapped explicit error and 404 `{"error":"missing item"}` for `Errorf`; Inertia returned the matching `Errors/BadRequest` and `Errors/NotFound` pages with those messages in props. Cause-only JSON returned 400 `{"error":"Bad Request"}`, its Inertia page had no message, and an explicit 500 returned only `Internal Server Error`. Field validation, wrapped sentinel mapping and redirects are covered by package and generated-handler tests. This does not override the historical audit or constitute full beta.7 acceptance. Full `go test ./layout/...` still fails unrelated `TestGeneratedLoginRacesAreClosed` assertions for concurrent auth-template changes; goldens were not regenerated.
