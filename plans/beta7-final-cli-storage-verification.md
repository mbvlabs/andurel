### Shared-daemon scope follow-up

An initial restricted API probe demonstrated the scope check but did not establish the complete startup path. Direct `unshare --pid --fork true` failed with `unshare: unshare failed: Operation not permitted`; Docker supplied separate namespaces instead.

The subsequent full public-startup probe used the random hostname `f6-c00d4b5e-7c60-4c8d-97ea-218c72015337`. Before starting, `docker ps -aq --filter label=dev.andurel.storagetest=true --filter label=dev.andurel.storagetest.host=f6-c00d4b5e-7c60-4c8d-97ea-218c72015337` returned no IDs. Two own Debian job containers shared the Docker socket, hostname and boot ID `bec34724-ae51-40bd-b457-a7d9673e1bd6`, but used PID namespaces `pid:[4026533158]` and `pid:[4026533164]`. The unique host gate prevented removal of any pre-existing user container. The `TestPublicScopeProbe` helper called public `NewCluster` and `NewTestDB` without manually labelling databases. Job A created `0ac7bfed3d0a` with PID 16, which was invisible in job B; two successive B processes each invoked unrestricted public startup while A stayed live. A, B and B2 each printed `SQL before OK`, `SQL after OK`, and `PASS`. Both B startups finished before A's after-check. All three clusters closed, and an inventory for the unique hostname was empty.

For same-scope crash recovery, `STORAGETEST_LEAK_HELPER=1 /probe/storagetest.test -test.run '^TestLeakClusterHelper$' -test.v` in job A created `5047c45809a3` through public `NewCluster` and intentionally panicked. The next public `TestPublicScopeProbe` startup in the same job reported `removed 1 leftover test container(s)`; Docker inspection confirmed the leaked ID no longer existed, and its replacement passed both SQL checks and closed.

Both storage packages were compiled with `go test -c` and their complete test binaries run with `-test.v` inside job A against reachable Docker: storage had 42 passes, zero skips; storagetest had 33 passes and three skips (the opt-in scoped probe, the panic helper when not invoked by its parent, and the opt-in public probe). All Docker integration tests, including `TestReapRemovesLeakedContainer`, passed. The unique-host inventory was empty afterwards; pre-existing `102d1efb15f8` was preserved. Only own job and database containers were cleaned up.
